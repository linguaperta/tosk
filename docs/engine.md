# Exercise engine (Phase 3)

`app/lib/engine/` generates, grades and sequences exercises from a `CourseData`. It is pure Dart (no Flutter, no drift) and depends only on `core/`. Import everything through `package:tosk/engine/engine.dart`.

## Layout

| File | What it does |
| --- | --- |
| `template.dart` | The `ExerciseTemplate` contract, `OptionPicker` (wrong-option filter), shared grading helpers |
| `templates/*.dart` | The ten templates (`listen_pick` since v0.5), plus `alterations.dart` (one-word sentence errors shared by spot-the-error and multiple choice) |
| `course_index.dart` | Cached derived lookups: verb-form and article occurrences in sentences, auxiliary positions, synonyms (through gloss/spelling indexes), distractor pools, sentences by translation, pro-drop and compound-contiguity statistics, and `memo` for templates' `canGenerate` answers |
| `gen_context.dart` | `GenContext` (course, options, seeded `Random`, facet states, skill, gate, sentence history) and `FacetStage` / `StagePolicy` |
| `gating.dart` | `SentenceGate` (grammar gating and the unknown-word cap) and `SentenceHistory` (recently seen sentences) |
| `selector.dart` | Picks the exercise type for a facet (stage affinity × focus weight × restrictions) and generates it |
| `focus_presets.dart` | Focus weights, parsed from `assets/config/focus_presets.json`, with identical embedded defaults |
| `grading/rating.dart` | `RatingPolicy` (result → FSRS rating, fast-answer table) and `GradeOptions` |
| `text/normalize.dart` | NFC, case, punctuation, apostrophes, accent folding, `matchAnswer` |
| `text/answer_diff.dart` | Word-level diff of a sentence answer (`diffAnswer`, `bestAnswerDiff`), display tokens (`textTokens`, `alignedTokens`), `facetOfToken`, `changedWords` (see "Partly right sentence answers") |
| `session/` | `EngineSession` (serve, grade, record, retries, result stream), the builders, `assessment.dart` (test out, placement, tough words), and `EngineSessionFactory` |
| `reference.dart` | Lookups for the UI's reference and word popovers: `glossForToken` (lemma, person, tense label, article, glosses), `CourseReference` (accent-insensitive search, verb tables with irregular forms, skills teaching an item, examples) |
| `reading.dart` | Reading any text: `ReadingLookup` (every written form of the course with all its readings), `ReadingText` (paragraphs, sentences, words, phrases, the share of known words); see "Reading" |
| `session/my_words.dart` | The learner's own words: `UserWordPool` (facets and exercises), `MyWordsBuilder` / `MyWordsSession`, `myWordsPerLesson`; see "My words" |
| `debug/exercise_printer.dart` | `exercisePrompt` (stored with mistakes), `formatExercise`, `sampleExercises` |

## Using it from the UI

```dart
final factory = EngineSessionFactory(
  course: courseData,                 // InMemoryCourseData from the data layer
  store: progressRepo,                // ProgressStore
  scheduler: fsrsScheduler,           // Scheduler: retrievability orders filler and fading
  options: SessionOptions(sourceLang: 'en', accents: AccentStrictness.lenient),
  presets: FocusPresets.fromJsonString(await rootBundle.loadString('assets/config/focus_presets.json')),
);
final session = await factory.lesson('present-are', focus: LessonFocus.grammar);
session.results.listen((event) { /* XP, combos, streak: event.streak */ });
for (var e = await session.next(); e != null; e = await session.next()) {
  final result = await session.submit(e, answer, elapsed: stopwatch.elapsed);
  if (!result.correct) explainer.explain(session.mistakeContext(e.id)!);
}
final summary = session.summary();
```

`myWords(length:)` returns a `MyWordsSession` (see "My words"). `lesson`, `lab`, `nonStop`, `fading`, `review`, `testOut`, `placement` and `toughWords` return `LessonSession`, `LabSession`, `NonStopSession`, `FadingSession`, `MistakeReviewSession`, `TestOutSession`, `PlacementSession` and `ToughWordsSession`, all `EngineSession`s. Beyond `PracticeSession` they offer `results` (a broadcast stream of `AnswerEvent`), `mistakeContext(exerciseId)`, and on non-stop `unlockedSkills()` and `enqueueBonus(types:, count:)`. Test out and placement are `AssessmentSession`s with an `outcome` once they end. `lesson(length:)` takes the lesson length (the UI offers `SessionLength` quick 5, normal 12, long 20).

UI notes on the exercise contract:

- **Conjugation pick:** an empty ending (Dutch `ik werk` = `werk` + '') is shown as the option `–` (`kNoEnding`).
- **Conjugation grid:** `tiles` holds one tile per asked cell, so a form shared by several cells (`werken` for wij, jullie and zij) appears once per cell, plus the distractors. A UI that consumes tiles works, and so does one that reuses them. Tapped tiles are graded with exact diacritics, typed ones by the accent setting. `cellCorrect` gives per-cell feedback.
- **Cloze:** `options == null` means free text (a `TextAnswer`, which may carry ink `candidates`; for keyboard and ink learners). The hint of a `#prod` or `#article` gap is the gloss that matches the translation (`lo` in "I know it": `it`), or all glosses when none does (`it, the`).
- **Spot the error:** render with `tokenPre[i] + tokens[i]`, or use `renderSpotError`.
- **Match pairs:** `MatchAnswer.missed` (left indices with a wrong attempt) is what grading uses; `wrongPairs` (left, right) lists the wrong pairs tried, for display, and becomes the stored answer text (`ciao = thanks; …`) when present.
- **Transform:** `change` (tense or person), `fromLabel` and `toLabel` (the course's tense or person labels in the source language; for a person change with a tense change both, `io, present`) drive the UI's from → to banner; the instruction is "Change the tense" / "Change the person" (`transform.tense` / `transform.person` in `strings.dart`). `targetDescription` stays for older snapshots.
- **Article multiple choice:** the prompt is `___ ragazzo` and `hint` is the meaning.
- **Lenient accents:** `Result.accentSlip` means "accepted, but watch the accent".
- **Listen and pick (v0.5):** speak `text` in `languageCode` (the course's `meta.target`) with text-to-speech; never show `text` before checking. `options` are target-language sentences (or words when `isSentence` is false); `translation` and `tokens` (the right sentence, tap-for-gloss) are for after checking.
- **Token alignment (tap-for-gloss).** Exercises that show a target-language sentence carry its tokens as `TokenRef`s (text, whitespace before, aligned item id and `'{tense}.{person}'` form, from `Token.lex` / `Token.form`; `tokenRefsOf(sentence)`): `ClozeExercise.tokens` with `gapFrom..gapTo` (the whole correct sentence; the gap covers those tokens, or only the start of token `gapFrom` for an elided article), `SpotErrorExercise.tokenRefs` (parallel to `tokens`; the wrong word carries the original token's alignment), `MultipleChoiceExercise.sentenceTokens` (sentence variant: the prompt when recognizing, the correct option when producing), `TransformExercise.sourceTokens` and `SentenceBuilderExercise.answerTokens`. All optional (null from hand-made exercises). `glossForTokenRef(course, ref, lang)` resolves one for the UI. The UI never makes the exercise's own item tappable before the answer is checked.

## Facets, templates and stages

| Facet | Templates |
| --- | --- |
| `#rec` | flashcard, multiple choice (word or sentence → meaning), match pairs, listen and pick (only with `SessionOptions.listening`) |
| `#prod` | flashcard, multiple choice (meaning → word, translation → sentence), sentence builder, cloze |
| `#form:{tense}` | conjugation pick, conjugation grid, cloze, spot the error, transform |
| `#article` | multiple choice (`___ noun` over `meta.articles`), cloze (the article token), spot the error |
| `#infl:{table}` | conjugation pick (the ending of a non-base cell), conjugation grid (tables of 3+ cells), cloze, spot the error |

`Skill.exercises` restricts the types for a skill. Lessons respect it; the lab overrides it, because choosing types is the point of the lab.

**Stages** (`StagePolicy`): a facet is *fresh* when it has never been reviewed, *learning* while its stability is under 5 days, and *stable* after that. `kStageAffinity` weights the types per stage: fresh facets get flashcards, multiple choice, conjugation pick and a grid with prefilled cells; stable facets get the sentence builder, cloze, a full grid, transform and spot the error. The selector multiplies that weight by the focus weight and draws one type. If no type has weight under the focus (say, a vocabulary focus on a pure grammar skill), it ignores the focus, and as a last resort it tries every allowed type.

Cloze uses free text only when the preferred input is keyboard or ink ("typing is never required": with tap input it always offers choices). For keyboard and ink, `StagePolicy.freeTextDays` (default 0, meaning always) can hold free text back until the facet reaches that stability.

## Template rules

Every wrong option goes through `OptionPicker`. It rejects an option that is empty, that equals a correct answer after folding case, punctuation and diacritics, or that duplicates another option, so the correct answer appears exactly once. What counts as "correct" for each template:

- **Flashcard:** the front is the lemma with its article (`il ragazzo`) and the back is all glosses. Graded by self-grade only.
- **Multiple choice:**
  - *Word, recognize:* wrong meanings come from items of the same POS (shared tag first, then similar frequency) that are not synonyms. A synonym is an item with an overlapping gloss in any language, parenthesized parts ignored, or the same spelling. No meaning of the target or of any synonym is offered (`dag` also means `hi`, through `hallo`).
  - *Word, produce:* no spelling of the target or of a synonym.
  - *Sentence:* other sentences whose aligned items and forms are not equivalent (synonyms count as equal), with distinct translations. Producing a sentence also offers the same sentence with one verb form or article swapped.
  - *Article:* the course's other articles.
- **Match pairs:** five `#rec` facets, from the skill first, then from other skills. No two items on the board may overlap, and no displayed meaning may be a meaning of another board item or of its synonyms. Each pair grades its own facet.
- **Conjugation pick:** only cells with a stem/ending split and a single word. Wrong endings come from other persons in the same tense, then other tenses, then same-class verbs, then any verb; another verb's ending only when its stem ends like this one (both in a vowel or both in a consonant: `ga` + `n`, never `denk` + `n`). An ending is never offered when stem + ending is an accepted form of the asked cell, which covers homographs such as Dutch `eet` (ik = jij = hij) and alternative spellings.
- **Conjugation grid:** distractors that match no form of any cell. In priority order:
  - the person-dependent word of a compound form swapped with another verb's (`sono mangiato`), skipped when the verb's `auxiliary` has a `|` because both would be right;
  - the stem with another class's ending (`mangete`, only from a stem that ends alike) or another person's ending (`maaken`);
  - the verb's other tenses with the same word count;
  - other verbs' forms.
- **Sentence builder:** the sentence's word tiles, the first one (and the first of a later sentence in the text, `"Was Bill in Japan?" "Ja, …"`) lower-cased unless it looks like a proper noun, plus wrong tiles: other persons' verb forms, wrong articles and related words. A wrong tile is never a word of the sentence or of another sentence with the same translation (`Come stai?` / `Come sta?`), a spelling of a synonym, or a word of an accepted verb form in the sentence. Accepted answers are the sentence plus any other sentence with the same translation whose words fit the tiles. Grading joins the words, so `l'` + `acqua` and `l'acqua` are equal.
- **Cloze:** the gap is an aligned token, rendered so that `before + expected + after == sentence.text`.
  - `#form`: a contiguous multi-word form is one gap. For a split form (`heb … gegeten`) only the person-dependent word is gapped. Options of another tense must have the gap's word count (`Ik ga` would fit the gap of `Ik ben gegaan`).
  - `#prod`: verbs offer the same cell of other verbs; other words their lemma or plural.
  - `#article`: an elided article inside a token (`l’acqua`) can be gapped too.
  - Wrong forms exclude every accepted form of the cell and of persons that share its pronoun (Dutch `hij/zij` and `zij`).
- **Listen and pick** (`templates/listen_pick.dart`, v0.5): only when `SessionOptions.listening` (the UI sets it when the device has a text-to-speech voice for the course language; Sarnami never), so `canGenerate` is false otherwise and the selector picks another type. Fresh facets hear the word (the lemma; wrong options are other lemmas of the same part of speech, similar ones first: within two letters in length and sharing the first letter or the last two, never a spelling of the item or a synonym); other facets hear a sentence with the item (`sentenceShare` 0.75), chosen like every gated sentence (`sentenceOk`, `prefer`, `useSentence`). Wrong sentences: at most one copy of the sentence with one verb form or article swapped (`formSwaps`, tenses only when `tenseShowable`, never right after an elided word: `c'siamo`), then other sentences whose grammar the learner knows (`featuresKnown`; their words may be new), not equivalent, within two words and 0.6–1.6× the length, sharing an aligned word first. **No two options may sound alike:** options are compared by `soundKey` (`foldAnswer`, then per word a silent `h` dropped, final `d`/`dt` read as `t`, `ij`/`y` as `ei`/`i`, doubled letters collapsed, words joined), so `ha`/`a`, `è`/`e` or Dutch `wordt`/`word` never stand side by side. Grading is `gradeChoice`; the fast-answer threshold is 8 s (listening takes time).
- **Spot the error:** one word is replaced, by the matching word of another person's form in the same tense or by a wrong article. Never by another tense: `De leerlingen mochten …` for `mogen` is grammatical and wrong only against the translation. The same exclusions apply (Italian `sono` is io and loro). Elision spacing is fixed through `tokenPre`. The translation is always shown, because in pro-drop sentences the error is defined relative to it (`Mangiate alle otto.` is grammatical on its own). So a swap to a person the translation may mean as well is never made when the sentence names no subject pronoun (`CourseIndex.sharesTranslation`: the pronouns in parentheses of both person labels, English "you" for Spanish tú, usted, vosotros and ustedes; every person spelled like the new form counts, `hacía` is yo and usted): `¿Por qué no cierran la ventana?` is no error for "Why don't you shut the window?".
- **Transform:** built only when the result is reliably constructible:
  1. *Same word count:* the words are replaced in place, wherever they stand.
  2. *Compound → single word:* the finite (first) word is replaced and the rest removed. This is valid for V2 and subordinate clauses.
  3. *Single word → compound:* only when the course's own sentences show that tense's compound forms as contiguous (≥ 90 %, so Italian yes and Dutch no) or the verb ends the sentence, and no clitic pronoun precedes the verb.
  4. *Person changes:* only in pro-drop sentences. The course must usually omit the subject pronoun for both persons (`dropsPronoun`, learned from the data, counting the pronouns of the person key and its labels, `jij/je`: never for Dutch), only adverbs, conjunctions and prepositions may precede the verb, and the sentence may contain no pronoun and no name (`Heeft Tom …`). Also not:
     - from a form another person shares (`sono`: io and loro, so `Dove sono i vostri nipoti?` may be misaligned);
     - from a third person when the sentence has a noun (it may be the subject), or when a translation says "it", "there" or "het" (impersonal: `Sembra ieri`, `È ora di …`, `Son las diez`), or when no translation has a pronoun of the person's label (he/she/you, they: `Aún queda mucho por hacer` is "much remains to be done"), or for "to be" with an infinitive after it (`Es necesario estudiar`);
     - singular ↔ plural when an adjective or participle may agree with the subject (`Dice di essere bravo`) or the verb is "to be" (`Non siamo parenti`).
  5. *Tense changes* only when every other verb in the sentence is in the source or the target tense and has a known form (`Wie was de filosoof die ooit geleefd heeft?` would mix tenses); not for an auxiliary verb next to a participle (`als ik nee had gezegd`), not into a compound form next to a participle (passive `gezegd werd`), and not from a form spelled like the infinitive (`vertellen` may be an infinitive after a modal). A form written out of order (`opgestaan ben`) is only rewritten into the same tense. A form shared by another person is only rewritten when that person's target form is the same (`werken` → `werkten` yes, `sono` → `ero`/`erano` no).
  6. *One finite verb:* the transformed verb (with its auxiliary) must be the sentence's only finite verb, or the other one keeps its tense or person (`Il dolore va e viene` → `va e è venuto`).
  7. *Time adverbs* (course data: `meta.time_adverbs`, from course.yaml `time_adverbs`, adverb → the tenses it fits, matched as whole folded words, multi-word keys allowed): a tense change never produces a tense the sentence's adverbs don't fit (`Adesso mangio` never becomes a past, `Ieri ho mangiato` never the present).
  8. A changed word after an elided one must start with a vowel or `h` (`l'ha fatto` → `l'faceva` is not built), and a word that elides must not stay whole before a changed word that starts with one (`Je vais` → *`je allais`). Which words elide is read from the course (`CourseIndex.elidingWords`: the lemmas of aligned tokens with a final apostrophe, French je/me/ne/que/…, Italian lo/la/ci); `CourseIndex.breaksElision` applies the same check to the swaps of spot the error and the sentence multiple choice (no `Je êtes`, `Ce n'suis`), and spot the error offers no elided article before a consonant (`l'monde`).

  Gendered alternatives (`sono partito;sono partita`, `seront arrivés;seront arrivées`) become extra accepted answers. A third-person target form with gendered alternatives is not built when the sentence has a noun, a name, the feminine pronoun of a two-gender person (`Elles arrivent`, person `ils/elles`) or a translation with "it" (`Le cose succedono` → `sono successi`, `Come va?` → `è andato`).

**Grammar gating of wrong options.** Under a gate, wrong options and tiles never show a form of a tense the learner has not met (`SentenceGate.tenseShowable`: the tense is known, and so are its irregular forms when the course teaches them as a feature, `irregular:futuro`): cloze options of another tense, conjugation-grid distractors from the verb's other tenses, conjugation-pick endings of other tenses, sentence-builder tiles and multiple-choice sentence alterations swapped into another tense. Wrong target-language sentences in multiple choice use only known grammar features (their words may be new).

**Occurrences.** `CourseIndex.formOccurrences` matches aligned tokens against the cell's accepted forms, in any order (Dutch subordinate `gegeten heeft`). When only the participle is aligned, it finds the auxiliary nearby. A token whose text is not an accepted form of its aligned cell, such as Dutch inverted `Werk jij?` aligned to `jij: werkt`, is never used, and neither is a compound form whose later word follows a determiner (`Hebben dieren een geweten?`: a noun).

**Compound tenses.** The pipeline aligns a compound form on its participle (`mangiato` → `passato_prossimo.io`, the cell's form being `ho mangiato`) and the auxiliary separately to the auxiliary verb's present (`ho` → `avere`, `presente.io`). `CourseIndex.auxiliaryPositions(sentence)` finds those auxiliaries (the nearest token within 6 that reads the form's other word, for the first accepted spelling whose words are all present). They belong to the compound form: they are never an occurrence of the auxiliary verb's own present (`Zijn jullie … geweest?` is no `zijn` present exercise, and `Ho mangiato` no `avere` one), so cloze, spot the error and transform only touch them through the compound form. The validator applies the same convention independently (`_ownerCell`).

## Recognition-only skills and moods (pack format 1.1)

- **Recognition-only facets** (`meta.recognition_skills`, docs/pack-format.md 12.5; `CourseIndex.recognitionOnly`): a facet of a recognition skill, or a `#form` facet of a recognition tense (`recognitionTenses`: the tenses of recognition verbs skills, the Italian passato remoto). `ExerciseSelector.allowedTypes` restricts them to `kRecognitionTypes` (flashcard, multiple choice, match pairs, listen and pick) **before** the skill's `exercises` list and the lab's free choice (`ignoreSkillRestriction`), so every mode (lessons, non-stop, review, the lab, test out, placement, tough words, starred) obeys it.
- **Multiple choice on `#form`** serves only recognition facets (`canGenerate` is false for every other `#form` facet, so other packs are unchanged). Three variants, drawn at random with fallbacks: a sentence with a form of the tense → its translation (`mc.sentence.rec`; `formOccurrencesIn`, gated like every sentence); the form → the same person's form in the skill's `equivalent_tense` (`mc.form.equivalent`: `andò` → `è andato`; only when that tense is showable); the form → its person (`mc.form.person`, labels via `personLabel(tense:)`). Persons that share the prompt's spelling are all right, so their answers are never wrong options. `template_validity.dart` checks the variants and that no recognition facet ever gets another type.
- **Transform between moods** (`meta.tense_groups`, `CourseMeta.tenseGroup`): a tense change is planned only when source and target tense are in one group (packs without the key: one group). Italian keeps the indicative tenses together and puts the conditional, each subjunctive tense and the imperative apart, so `Mangio` never becomes `*Mangi` and `Se piove resto` never `*Se piove resterei`; a passato remoto sentence may still be turned into the passato prossimo.
- **Tense-specific person labels** (`meta.tense_person_labels`, `personLabel(person, lang, tense:)`): grids, endings, transforms and the reference show the Italian imperative's `lui/lei` row as `Lei (you, formal)`. Persons whose labels in a tense share a word in parentheses are ambiguous in that tense (`ambiguousPersons(person, tense:)`, `sharesTranslation`): an imperative has no subject, so for "Speak!" `Parla!` (tu), `Parli!` (Lei) and `Parlate!` (voi) are all right and never wrong options or errors of each other. For the same reason spot the error skips every tense listed in `tense_persons`: a person swap there is a grammatical sentence of another person (`Fate come dico` → `Facciamo come dico`). Italian also labels `tu (you)` and `voi (you, plural)` in every tense (`person_labels`), so a sentence without a subject pronoun never swaps them for an English "you".
- **Gloss language** (`glossLanguage`): a pack may lack some glosses or translations in the learner's language (Italian units 10-15 are English only, `required_translations`); the app then shows English. Multiple choice (words and sentences) and match pairs take the wrong options in the language the right one is shown in, so no option stands out.
- **Started skills** (`SentenceGate.startedSkills`, also `markStarted` during a session): a practised facet starts only the skill that introduces it (its first skill in course order). A late skill that shares a facet with an early one (Italian `progressive` trains `stare#form:presente`, also in `irregular-present`) is not started by early practice, which would otherwise make its grammar and all its prerequisites' grammar known.

## Inflection tables (`templates/inflection.dart`)

`#infl:{table}` facets (docs/ARCHITECTURE.md, "Inflection tables") reuse four templates; the exercises are the same classes, with `inflection: true` on `ConjPickExercise` and `ConjGridExercise` (`tense` = the table, `person` = the cell, labels from `meta.inflection_tables`). Grading is unchanged.

- **Pick the ending** (`ragazz___` · plural, `bell___` · feminine plural, `wit___` · with -e, `boom___` · diminutive): only non-base cells with a stem/ending split. Wrong endings: the item's other cells, the cell's `wrong` forms, then the same cell of other items whose stem ends in the same letter. An ending is never offered when stem + ending is an accepted form of the cell (`grande` is m.sg and f.sg). The UI shows one chip (the cell) instead of person + tense.
- **Grid:** tables with at least 3 cells (Italian agreement); the base cell is always given, of the others about half (fresh) or a third (learning) are prefilled. Distractor tiles: the cells' `wrong` forms, then other items' forms of the same table.
- **Cloze and spot the error:** tokens aligned to `infl:{table}.{cell}` whose text is an accepted form (for agreement tables the canonical form only, so `bel` before a noun is left alone); non-agreement tables never ask the base cell. Wrong options / the replaced word: the item's other cells for an agreement table (`La casa è ___`: bello, belli, belle), and the cell's `wrong` forms for every table (`Ho due ___`: gatti vs `gattoi`). Never a real word of another lemma (`gatte`), never a singular for a plural: both can be right against the sentence. The cloze hint is the lemma, plus the cell for meaning tables (`gatto (plural)`). These facets can always fall back to the picker, so their sentence templates skip sentences shown in this session or among the last 100 (`GenContext.shownRecently`): few sentences show a given plural or diminutive.
- `test/engine/template_validity.dart` checks them independently: the gap or error token is aligned to the item and cell, every wrong option is another cell of an agreement table or no word of the course at all (`_courseWords`), the base cell is never picked and always given in the grid. Fixtures: `test/engine/fixtures/inflection_course.dart`; `test/engine/inflection_test.dart`.

## Grammar gating and sentence variety

**Topic trees** (schema minor 3): topic skills are ordinary skills after every main-tree skill in course order, so a facet a topic shares with the main tree is introduced (and "started") by its main-tree skill, and a word the learner knows from any tree is no fresh facet in another (lessons don't introduce it again). Gating needs no change: a sentence with a topic word counts it as unknown vocabulary until the topic skill is started, like any word. The validator gives such a sentence one home skill per tree (docs/pack-format.md 3.3).

`gating.dart` implements the contract in docs/ARCHITECTURE.md ("Grammar gating"). Every session calls `prepare()` before its first exercise (`next()` does it):

- **Gate** (`SentenceGate`, only when the course has `meta.base_features`; older packs are not gated):
  - *Started skills*: the skill that introduces each reviewed facet (`store.allStates(courseId)`; its first skill in course order, see "Recognition-only skills and moods"), plus the introducing skill of every facet answered during the session (`markStarted`, so non-stop opens a skill's grammar after its first answer).
  - *Current skills* (`EngineSession.currentSkillIds`): the lesson's skill, the lab's skills; none for non-stop, fading and mistake review.
  - `knownFeatures` = `base_features` ∪ the features of the started and current skills and of their prerequisites (transitively, like the pipeline's home-skill rule).
  - `knownItems` = the items of the started and current skills.
  - A sentence is allowed when its features ⊆ `knownFeatures` and its unknown words ≤ the cap: `SentenceGate.capFor(focus, skill)` = 1 for a grammar focus or a grammar skill, else 2. A word aligned to an unknown item counts 1. An unaligned word counts 0 when it is a name or a number (a capitalized word inside a sentence, a sentence-initial word that also appears capitalized inside one, or digits) and 2 otherwise: in the packs those are rare (125 it / 329 nl sentences) and often an untagged grammar form (passato remoto `Comprai`), so such a sentence never passes the grammar cap.
  - Cloze, spot the error, transform, the sentence builder and sentence multiple choice only use allowed sentences; transform also needs its target tense and the facet skill's features to be known. `canGenerate` answers are memoized in the gate (`GenContext.memo`), so a template without an eligible sentence returns false and the selector picks another type. A lesson never falls back to ungated sentences: conjugation grids and picks, flashcards, word multiple choice and match pairs fill it.
- **Variety** (`SentenceHistory`): a bounded LRU of the last 1000 sentence ids per course, stored as a JSON array in the settings key `engine.recent_sentences.{courseId}` (no schema change). `GenContext.prefer` ranks candidate sentences by 0.75 × unknown words + a recency penalty (0 unseen, 1–3 seen, higher when seen more recently) + a random jitter below 1. A sentence that shows a non-base feature the exercise's skill introduces gets `kSkillFeatureBonus` = 1.25 off (the Italian `progressive` skill trains `stare#form:presente`; `Sto mangiando` comes before `Come stai?`). Generated sentences (`src` starting with `claude-gen`, written for the course by the pipeline's `gen` command where Tatoeba has too few easy sentences) add `kGeneratedSentenceWeight` = 1, so an unseen real sentence with as many unknown words always comes first, and a generated one ranks about level with a real one seen long ago. Sentences already shown in this session come last, so a session repeats a sentence only when the facet has nothing else. Templates record what they show (`GenContext.useSentence`). The session saves its sentences when `next()` runs out and on `stop()`: read, merge (moving re-seen ids to the end), trim, write, serialized per key, so concurrent sessions keep each other's exposures. A mistake re-ask is a new exercise and usually gets another sentence.
- **Exercise types:** the selector tries the previous exercise's type only after every other type of the same weight tier failed, and each of the last three types weighs 0.6× per occurrence. A retry is the exception: it asks for the missed type first ("Retries" below).

`test/engine/gated_validity.dart` checks gated exercises against an independent computation of the learner's knowledge. `real_pack_gating_test.dart` runs it on the bundled packs for a fresh learner and for learners who started units 1..k, plays full lessons (every unit-1 skill for a fresh learner, every unit-3 skill after units 1–3) and a non-stop run, and checks variety across lessons. `runTemplateValidity` stays the "everything known" check.

## Grading and recording

`RatingPolicy`: a wrong answer is Again; a right one is Good, or Easy when faster than the type's threshold (`defaultFastMs`, configurable). An answer accepted only through accent folding is capped at Good, and flashcards keep their self-grade. Tapped tiles and choices are compared with exact diacritics. Typed and ink answers follow `AccentStrictness`: strict means exact diacritics; lenient folds them and sets `accentSlip`. Both always normalize NFC, case, punctuation, whitespace and apostrophe variants. Ink answers are accepted when any of the top-k candidates matches.

`submit()` writes `ReviewEvent`s through `ProgressStore.record()`, each with a UUID v4 id, the session id, the mode name, the exercise type, the input mode, the response time and the answer text.

**Re-ask policy (no double penalty).** Per facet, per session:

- The first wrong answer writes one Again event and one `MistakeRecord`, with the same id as the event. The record holds the prompt from `exercisePrompt`, the expected and given answers, the skill and its grammar note.
- After that mistake, wrong answers on the same facet write nothing.
- The first fully right answer after the mistake (a retry or any later exercise on the facet) writes one Good, never Easy, as the relearning step.
- Later answers on that facet in the session write nothing.
- Facets with no mistake write an event for every answer, except in a retry (below).

So **only the first attempt is graded**: the retry is practice. The one event it can write is the FSRS relearning step of a facet that already has its Again, which is the existing design (a short-term "I got it back" signal to the scheduler) and is kept. A retry of an exercise whose own facet was not rated wrong (a partly right sentence whose tested word was right) writes nothing for that facet.

### Retries (mistakes come back until they are right)

`EngineSession` re-queues every wrong exercise as a **retry** (`SessionSlot.reask`): the facets with a wrong outcome (not the [secondary](#partly-right-sentence-answers) words of a partly right sentence), or the exercise's own facet when the answer was wrong but no such facet was (a partly right sentence whose tested word was right, a word-order error). A retry is a fresh exercise on the same facet that tests the same thing: the type that was missed when the template can build it (`SessionSlot.retryType`, usually another sentence through the variety rules), any allowed type otherwise; a slot's `only` restriction (lab types, a bonus round) still holds.

- **Finite sessions** (lesson, lab, fading, mistake review, starred, tough words): retries come **after the planned exercises**, in the order the mistakes were made; a retry answered wrong goes to the back of the queue again. The next retry is never the facet just asked while another one is waiting.
- **Endless sessions** (non-stop): retry *n* of a facet comes `endlessRetryGap(n)` = 4–8, then 8–16, then 16–32 exercises later (uniform in the range), before the next planned slot.
- **Cap:** at most `maxReasks` = 3 retries per facet per session, one waiting at a time. After the cap the facet is not asked again in the session; its `MistakeRecord` keeps it open for mistake review (a same-session right answer never resolves a mistake, see below). Test out and placement have no retries (`maxReasks: 0`).
- **Progress:** every queued retry adds 1 to `plannedLength` (a retry that can no longer be built takes it back out; an override drops the exercise's waiting retries), so the bar's total grows honestly with each mistake. `RetryingSession.pendingRetries` (waiting now) and `isRetry(exerciseId)` let the player show the count and mark the retry (docs/ui.md).
- `AnswerEvent.isReask` is true for a retry.

### Partly right sentence answers

Exercises whose answer is a sentence or phrase (sentence builder, transform, cloze with typing; tiles, typed or written) are compared **word by word** when wrong (`text/answer_diff.dart`, the model in `core/models/answer_diff.dart`):

- **Tokens:** split on whitespace with elisions split off (`l'acqua` = `l'` + `acqua`, so tiles `l'` `acqua` and typed `l'acqua` agree; a single consonant after the apostrophe is one Dutch word: `foto's`, `m'n`); pure punctuation is shown but never compared. Words are compared by the answer key of the accent setting (`answerKey`: tapped tiles strict, typed and ink by `AccentStrictness`), so case, punctuation, apostrophe variants and, when lenient, accents never make a word wrong; under strict accents `citta` for `città` is a wrong word.
- **Alignment:** a longest common subsequence of the words. An unmatched word that the other side has unmatched too is **moved** (a right word in the wrong place, both lines). The rest of each run between matches pairs up in order as **wrong** (learner) / correction (accepted answer); leftovers are **extra** (learner) or **missing** (accepted answer, with a marker in the learner's line where they belong).
- **Closest answer:** the diff is taken against every accepted answer (the sentence builder's canonical sentence is its real text with case, punctuation and alignment; other sentences with the same translation; a transform's gendered alternatives; a cloze's accepted forms) and the one with the fewest places to fix wins (then most words in place, then the first). `Result.diff` carries it (null for right answers).
- **Partial** (`AnswerDiff.partial`): at least one word in place, at least half the words right (in place or moved), and at most `min(4, max(1, words ~/ 2))` places to fix (wrong + extra + missing + moved). Only then does the UI mark the places and the engine give per-facet credit; otherwise the answer is graded and shown as a whole.

**Per-facet credit** (`partialOutcomes`, `PartialCredit`): when the diff is partial and the template can map words to facets:

- *Sentence builder* (`creditByAlignment`, only against the canonical sentence, whose `answerTokens` carry the pipeline alignment): the words aligned to the tested facet's item carry the tested facet. Every other aligned word maps to `facetOfToken`: a verb form `'{tense}.{person}'` to `{item}#form:{tense}`, an inflected word `'infl:{table}.{cell}'` to `{item}#infl:{table}`, any other word to `{item}#prod`.
- *Transform*: the words the transform changes (those not in a common subsequence with the source sentence) carry the tested `#form`; the rest is copied from the given sentence, so a slip there is no lapse of any word.
- *Typed cloze, and a sentence builder answer closest to another accepted sentence*: no mapping, so whole-answer grading, but the diff is still shown.

The outcomes: the **tested facet** is right when all its words are right (in place or moved): `correct: true`, `partial: true`, rating **Good** (never Easy: the answer was wrong); otherwise Again. Each **other facet** with a wrong or missing word gets Again as a `secondary` outcome. A right other word earns nothing (a fully right answer doesn't rate the other words either, so a partly right answer never earns more reviews than a right one). Recording (`EngineSession.submit`):

- The tested facet's partial outcome is written with rating Good but **`correct: false`**: the answer was a mistake, so XP (no XP for a wrong event), accuracy stats, perfect lessons, the non-stop replay and mistake resolution treat it as one, while FSRS counts no lapse for the word the learner got right. No `MistakeRecord` is stored for it, and it is no relearning step for a facet that already has a mistake.
- A secondary outcome is recorded only for a facet the course trains (`skillsForFacet` non-empty) that the learner has studied (a state exists): a lapse never introduces a word. It writes Again and a `MistakeRecord` (with the word's own skill and note) under the usual no-double-penalty rule, so mistake review asks that word later. It is never re-queued as a retry of its own; the exercise is.
- The exercise as a whole is a mistake: `Result.correct` is false, the streak breaks, and it comes back as a retry.
- "I was right" overrides the tested facet's event (it is `correct: false`) like any wrong event and drops the exercise's retry.

Tests: `test/engine/session_test.dart` (group "retries": at the end of the lesson with the missed type, again until right, the cap of 3 and mistake review afterwards, the order of several mistakes, `pendingRetries`, non-stop spacing 4–8 / 8–16 / 16–32 and no retry after a right one), `test/engine/answer_diff_test.dart` (tokens, wrong / missing / extra / moved words, reorderings, accents strict and lenient, case, punctuation and apostrophes, tile sources, the closest answer, `facetOfToken`, `changedWords`), `test/engine/partial_credit_test.dart` (outcomes of the sentence builder, typed cloze and transform; the review log: Good with `correct: false`, a studied wrong word's Again and mistake, an unstudied one ignored, the retry of a partly right answer recording nothing, "I was right"), `test/engine/real_pack_partial_test.dart` (a swapped tile on every bundled pack is a one-place partial answer, credited where the tested word was right).

## Sessions

- **Lesson** (`LessonBuilder(skill, focus)`): states are loaded once. About 12 exercises:
  1. due facets, most overdue first;
  2. up to 5 new facets in introduction order;
  3. filler: the weakest or least recently reviewed facets, then repeats of the lesson's new and due facets, without immediate repeats.
- **Lab** (`LabBuilder(skills, types, length)`): due facets, then new ones (round-robin across skills), then the weakest, cycled. Only the chosen types are used, overriding skill restrictions.
- **Non-stop** (`NonStopQueue`): endless. It serves due facets from unlocked skills and mixes in a new facet (the first unreviewed one in skill order) every 4th exercise; a new facet no template can build right now (`EngineSession.onGenerateFailed`) is skipped for the rest of the run, so it never blocks the facets after it. A learner who only plays non-stop works through the whole map (`test/app/practice_modes_progress_test.dart`); when nothing is due and nothing is new, it takes from the three weakest. A skill is unlocked when every prerequisite is *started* (at least one facet reviewed), re-evaluated after each answer. `enqueueBonus` restricts the next exercises to some types, for a progression bonus round.
- **Fading** (`FadingBuilder`, mode `review`): due facets, then the lowest predicted recall, across all skills. No new facets.
- **Mistake review** (`ReviewBuilder`, `factory.review(length:)`, mode `review`, `session/mistake_review.dart`): one exercise per *open* mistake, up to `length` (default 12). `openMistakes(store:, course:, scheduler:, now:)` lists them (the UI uses it for the count and the list):
  - It scans the latest 300 `MistakeRecord`s of the course and keeps the latest per facet, with a count.
  - **Resolution rule:** a mistake is resolved once its facet is answered correctly in a *later session*: a correct event not before the mistake whose session id differs from the mistake event's (the record id is the event id). The retry later in the same session does not count. A new mistake on the facet (also during review) opens it again.
  - Facets the course no longer trains (pack update) are skipped.
  - Order: still weak (predicted recall < 0.9, `kMistakeWeakRecall`) first, then the rest; most recent first within each group.
  - Each facet is asked with the exercise type that was missed when the skill allows it and the template can build it (`only: {type}`); flashcard mistakes (a self-graded Again) and types that can't serve the facet fall back to the normal selector. If the restricted generation still fails, the slot is retried unrestricted.

- **Starred practice** (`StarredBuilder`, `factory.starred(StarredPractice(itemIds:, sentenceIds:, exercises:), length: 12)`, mode `starred`, `session/starred.dart`; v0.4): the learner's bookmarks of the course. Three queues, interleaved (exercise, word, sentence, …), each facet planned once, up to `length`:
  - **Exercises** are served again exactly as starred (the decoded snapshot, `SessionSlot.fixed`; ids `starred:{bookmark id}`) when the course still trains every facet they grade and still has their sentence; otherwise a fresh exercise of the same type on the same facet. Facets the course no longer trains are skipped.
  - **Words**: every facet the course trains for the item, weakest first (reviewed facets by predicted recall, then new ones in course order).
  - **Sentences**: one facet per aligned word (a verb form asks its tense's `#form`, an inflected word its `#infl`, other words `#prod`, else `#rec`), as sentence exercises where one can be built (`kSentenceExerciseTypes`: cloze, sentence builder, spot the error, transform; any type otherwise). The starred sentences are the session's `preferredSentences`: `GenContext.prefer` ranks them first (`kPreferredSentenceBonus`) and lets them through the grammar gate, since the learner has already seen them.
  - Wrong answers are re-asked like in any session. Empty (`plannedLength == 0`) when nothing is starred. Tests: `test/engine/starred_test.dart`.

### Test out, placement and tough words (`session/assessment.dart`)

- **Test out** (`TestOutBuilder`, `factory.testOut(skillId, length: 10, passMark: 0.8)`, mode `testOut`): the skill's facets, production first (`#prod`, `#form`, `#article` shuffled, then `#rec`), cycled to `length`. Each slot asks for production-leaning types (`productionTypes`: sentence builder, cloze or multiple choice for `#prod`; grid, cloze, transform or spot the error for `#form`; …); when none can be built it is retried with any `kAssessmentTypes` type (everything auto-graded on one facet: no self-graded flashcards, no multi-facet match pairs). No re-asks (`maxReasks: 0`), so the score is first answers: `correct / answered`. When the last `next()` returns null the session concludes: at `score >= passMark` it **credits** the skill.
- **Placement** ("Find my level", `PlacementBuilder(config: PlacementConfig())`, `factory.placement(maxExercises: 40)`, mode `placement`; after v0.7.6): adaptive by unit over the **main tree** only (topic trees, `CourseTrees` in `core/trees.dart`, are side trees that open from their anchors once those are credited). See "Placement" below.
- **Credits** (`kTestOutCreditType`, a core constant): `ReviewEvent`s on every facet of the credited skills that is not learned yet (no state, or still in FSRS's learning phase), with `exerciseType: 'test_out'`, `correct: true`, `responseMs: 0`, input `self`, and the session's id and mode, written through `EngineSession.recordExtra`, never before the facet's last answer (1 ms after it when the clock hasn't moved). **Test out** writes one **Easy** per facet: a new or learning facet graduates straight into review (stability about 8.3 days), so the skill meets progression's bronze rule (every facet learned) and the skills requiring it unlock. **Placement** writes **Good, then Easy 1 ms later** (`kPlacementCreditRatings`): also graduated (bronze, unlocks), but with a stability of about 3.9 days, so the words come back for a light review in about 4 days instead of counting as known for a week (and no credited skill shows silver). **Self-declared** credits ("Skip ahead without a test") are **Good, Good** (`kSelfDeclaredCreditRatings`: stability about 2.3 days, back in 2 days) and carry `answer: 'self-declared'` (`kSelfDeclaredCredit`, `ReviewEvent.isSelfDeclared`), so the log says honestly that nothing was tested. Because credits are ordinary log events, they sync and replay like answers (`rebuildStates()` reproduces them); progression gives them no XP and doesn't count them as reviews (`docs/progression.md`). A stopped session (Quit) concludes nothing and has no `outcome`. Mistakes made during the quiz are recorded as usual and stay open for mistake review.
- **Tough words** (`ToughWordsBuilder`, `factory.toughWords(length: 12, minLapses: 4)`, mode `review`): `leechFacets` = facets of the course's skills whose state has at least `minLapses` lapses, most lapses first, then lowest recall (progression's `toughWords` uses the same rule for the UI's count). Each one becomes a recognition → production ladder (`leechLadder`): `#prod` = multiple choice on its `#rec` sibling, multiple choice on `#prod`, then cloze or sentence builder; `#rec` = multiple choice, match pairs or multiple choice, then production on its `#prod` sibling; `#form` = conjugation pick or grid, then cloze, transform, spot the error or grid; `#article` = multiple choice, then cloze or spot the error. Ladders are added whole until `length` is reached; a step that can't be built is retried with any type. Mistakes are re-asked as in any session.

### Placement (`PlacementSession`, after v0.7.6)

An advanced learner must not spend hours on basics, and a long course (it has 15 main units, French will have about 20) must be placeable to its end in a short test. The session works unit by unit over `CourseTrees.mainUnits`:

- **Probe.** Each tested unit is asked `probe` = 2 exercises first: its candidates (`placementCandidates`) alternate grammar and vocabulary skills, each skill production first, only facets the unit's own skills introduce (a word from an earlier unit belongs to that unit), so the first two are one grammar and one core-vocabulary exercise. Slots ask production types (`productionTypes`) and fall back to any `kAssessmentTypes` type. Grammar gating treats the learner as knowing the unit and every unit before it (`EngineSession.setCurrentSkills`), so a unit-10 sentence may use units 1–10, never later grammar.
- **Verdict.** 2 of 2 right: passed. 0 of 2: failed. 1 of 2: `extension` = 2 more; the unit passes with at most one wrong (3 of 4), and fails as soon as a second answer is wrong. A unit whose candidates run out is decided on what it has (75 %).
- **Jumps.** After `jumpAfter` = 2 clean passes in a row (every answer right) the test asks every second unit (`maxStride` = 2); a passed jump credits the unit it skipped (`UnitVerdict.inferred`: units build on each other), a failed one has the skipped unit asked next (back-test). The stride also grows when the units left would not fit the remaining budget at 2 exercises each (never before unit 1 has been asked).
- **Stop.** After `failuresToStop` = 2 failed units (a clear failure, not one slip), at the last unit, when fewer than 2 exercises are left of `maxExercises` = 40, or on "Stop here — place me now" (`PlacementControl.placeNow`; a unit under way counts only when its answers already decide it).
- **Credits** (`creditedUnits`): units passed or inferred before the first failure. After a failure a pass counts only once the next unit passes too: one lucky pass between failures (a guessed multiple choice) places nobody further, two in a row make the failure a **gap** (`gapUnits`: open to practise, its skills stay available). `outcome`: `passedUnits` (credited), `placedUnit` (the unit after the last one done; null past the end), `gapUnits`, `inferredUnits`, `knownUnits`, `failedUnit` (the first failed), `creditedSkills`, the score. Placement credits as above (Good + Easy, back in about 4 days).
- **Re-runs** ("Find my level again"): units whose facets are all learned already are skipped (`knownUnits`), so the test starts where the learner is; it only adds credits, never removes progress. Per-skill test out stays as it was.
- **Skip ahead without a test** (`SkipAheadSession`, `factory.skipAhead(unitIds)`): credits every skill of the chosen main-tree units as self-declared (Good, Good, marked `self-declared`) and returns an outcome with `selfDeclared: true` and the same `placedUnit` / `gapUnits` rules (`placementOf`). No exercises.

**Why these numbers.** With the probe and extension, a unit known at 90 % passes with probability 0.81 + 2·0.9·0.1·0.81 ≈ 0.96, one guessed at 25 % with ≈ 0.08 (and needs a second lucky unit in a row to place further). Two failures to stop means one slip doesn't end the test. Jumps keep a strong learner's test short: the perfect learner needs `2 + 2·⌈(n−2)/2⌉`-ish exercises.

**Simulations** (`test/engine/real_pack_placement_test.dart`, simulated learners on the bundled packs, and on a French pack in tosk-data/dist when one exists; `TOSK_EXTRA_PACKS` adds paths):

| Course (main units) | Perfect learner | Beginner | Knows units 1..k |
| --- | --- | --- | --- |
| it (15) | past the end, 18 exercises (6 units by a jump) | unit 1, 4 exercises | k = 5, 7, 10: placed 6, 8, 11 in 12–16 |
| nl (8) | past the end, 10 | unit 1, 4 | k = 2, 4, 5: placed 3, 5, 6 in 8–12 |
| es (9) | past the end, 12 | unit 1, 4 | k = 3, 4, 6: placed 4, 5, 7 in 10–12 |
| synthetic 20 / 24 / 30 | all credited in 22 / 26 / 32 | unit 1, 4 | k = 15 / 18 / 22: placed exactly, in 22 / 24 / 28 |

Noisy learners over 12 seeds: 90 % right everywhere places past the end in 11 of 12 runs; 90 % on units 1..k and 25 % beyond places within one unit of k+1 in most runs (it: 7–9 with two outliers at 11 and 12; nl: 5 except two runs at 7); the longest test was 36 exercises. A unit missing in the middle (unit 2 unknown, everything else known) is a gap: placed past the end with unit 2 left open. An unknown unit that a jump skipped is credited with the unit after it; the light-review credits and "Reset this skill" cover that case.

## Skill reset (`skill_reset.dart`, after v0.7.6)

"Reset this skill" for a learner the app over-estimated (placement, test out, luck). `resetSkills(store, course, skillIds, now:)` writes one **`reset`** event (`kResetType`) per facet of the skills that has a state (`resettableFacets`; shared facets included: a word is one word in every skill), all with one batch id as session id, mode `reset`, the skill id in `answer`, rating Again (unused), `correct` false, and `at` after the facets' last events. **Replay convention** (`resolveResets` + `replayStep` in core, `replayable` = overrides then resets): a reset clears the facet's state at its instant, so later answers start from scratch (`before` is null, a lesson introduces the word as new, tiers and strength drop); earlier events stay in the log, so XP, streaks and stats are unchanged (progression's `canonicalOrder` leaves resets out of the steps and `LogReplay` applies them to its states only, `activeResets`). **Undo**: `undoReset(store, resets, now:)` writes one `reset_undo` event (`kResetUndoType`) per reset with the reset's id in `answer`; replays drop both, so the state is exactly as before. Every store applies the convention: `ProgressRepo.record` (a reset in order deletes the state row; an undo replays the facet), `rebuildStates`, `importEvents` (sync merges, any order: an undo that arrives before its reset waits for it), `InMemoryProgressStore`, `replayLog`, `foldFacet`. `ProgressStore.record` returns `FacetState?` (null after a reset). Tests: `test/engine/skill_reset_test.dart` (both stores: reset → no state, tiers drop, XP and log kept, rebuild reproduces it; undo restores states and tiers; a lesson reintroduces the words and the first answer after it is a first review; a whole unit; the replay rules in any order; two devices through the fake sync backend, and a third that receives the undo before the reset).

## Typing mode, accent letters and overrides (v0.3)

- **Typing ("challenge") mode** is the UI setting "Answer input: Tap / Type" (`lesson.answer_input`), which sets `SessionOptions.preferredInput = keyboard`. The engine changes are small: cloze is free text for keyboard learners (as before, `freeTextDays`), and **conjugation pick grades a `TextAnswer`**: the typed ending (`-`/`–` = the empty ending, a leading hyphen ignored, the whole form accepted too) as `stem + ending` against `ConjPickExercise.accepted` (new optional field: every accepted spelling of the cell) with the accent setting and `accentSlip`. Grids (`GridAnswer(inputMode: keyboard)`, or `ink` with `candidates` per cell since v0.5) and the sentence builder and transform (`TextAnswer` through `gradeTiles`) already graded typed answers with the accent setting. Recognition types (flashcard, multiple choice, match pairs, spot the error) stay tap.
- **`specialLetters(course)`** (`special_letters.dart`): the target language's non-ASCII letters, lower-cased and NFC, counted over every spelling, plural, accepted verb form and sentence word, most frequent first; a letter needs ≥ 3 occurrences and ≥ 0.2 % of the top letter's count (drops loanword letters), at most 12. Real packs: it `è à ò é ì ù`, nl `ë ï é è ü`, hns `ṯ ê ã ṟ õ ḏ î é`. Cached per course.
- **Overrides** ("I was right", `OverridableSession` in `core/interfaces/session.dart`): `EngineSession.canOverride(exerciseId)` / `overrideAnswer(exerciseId)` write one `kOverrideType` event (Good) per wrong facet outcome the answer recorded (see ARCHITECTURE.md for the replay rule), count the answer as correct, drop the facet's queued re-asks and its mistake (so later answers in the session record as usual), and return the events. A wrong re-ask recorded nothing, so it only counts as correct. Tests: `test/engine/override_test.dart`.

## Handwriting and listening (v0.5)

- **Ink answers.** Handwriting is `SessionOptions.preferredInput = ink` (cloze then uses free text, like keyboard). Every free-text grader accepts recognizer candidates: `TextAnswer.candidates` for cloze, conjugation pick (each candidate as an ending or a whole form), the sentence builder and transform (`gradeTiles`), and `GridAnswer.candidates` (one list per cell, parallel to `cells`) for the grid, where a cell is right when its text or any of its candidates matches. Ink follows the accent setting like typing (lenient: an accent-only match is a slip). The UI sends the best reading as `text` and the next two as candidates (sentences written in parts: combinations of the parts' readings, the top five). `RecognizerAnswerInput` (core hook) keeps the top k. Tests: `test/engine/listen_ink_test.dart`.
- **Listening capability.** `SessionOptions.listening` (default false) gates `listen_pick`; sessions, the lab, assessments (`kAssessmentTypes` includes it) and mistake review simply never get the type without it. The validity suites (`runTemplateValidity`, `runGatedValidity`, the real-pack gating test and the sample printer) assume it is available, so `listen_pick` is checked on every course: exactly one option sounds like the spoken text (and is it), no two options sound alike, the sentence contains the item and its translation is the sentence's, the word is the lemma and no wrong option spells the item; under a gate, the spoken sentence and the wrong sentences only use known grammar (`gated_validity.dart`).

## Reference lookups (`reference.dart`)

- `glossForToken(course, itemId:, form:, word:, lang:)` → `WordGloss`: `headline` is `mangiamo → mangiare · noi · present` for verb forms (person key, tense label in the source language; non-finite forms only the tense), `case → la casa · plural` / `piccola → piccolo · feminine singular` for inflection cells (no label for the base cell), `il pane` for nouns (`CourseIndex.withArticle`), the lemma otherwise (the word is left out when it is the lemma).
- `CourseReference.of(course)` (cached per course): `items` and `verbs` sorted by folded lemma; `search(query, lang, verbsOnly:)` over lemmas, variants and plurals, every accepted verb form, and glosses in `lang` (a gloss matches by any of its words, so "eat" finds "to eat"), ignoring case and accents (`foldAnswer`), ranked lemma > inflected form > gloss (or a word of it) > lemma prefix > gloss prefix > anywhere, then by frequency; `verbTable(itemId, lang)` (finite tenses in `meta.tenses` order with persons in `meta.persons` order, then infinitive, participle, gerund); `skillsTeaching(itemId)`; `examples(itemId)` (shortest first).
- **Irregular forms** (`isIrregular`, a highlighting heuristic): only for verbs marked `irregular`. A single-word form is regular when it equals the verb's stem (declared, else its most common form stem) wrapped in a prefix/suffix pattern that at least 10 % of the course's regular verbs of the same class use for that tense and person (all classes when the class has no regular verbs; prefixes cover Dutch `ge…t`). A compound form is irregular when it contains an irregular participle. Without a stem or a pattern nothing is marked.

- **Glossing free text** (`word_lookup.dart`, v0.4, for AI conversation replies): `WordLookup.of(course)` maps written forms to items: lemmas, spelling variants, plurals, every accepted verb form (with its `'{tense}.{person}'` key) and inflection cells (`'infl:{table}.{cell}'`), lowercase only (accents matter: `è` is not `e`), the more frequent item winning a shared form. `tokenize(text)` splits text into `TokenRef`s (words aligned when known; whitespace in `pre`; punctuation as non-word tokens; `l'acqua` becomes `l'` + `acqua`), so `renderTokenRefs` gives the text back and `TappableSentence` shows glosses.

## My words (`session/my_words.dart`, after v0.7.6)

The learner's own words (`core/models/user_word.dart`; storage in docs/data-layer.md, "My words") are practised like pack items, without being course items:

- **Facets and ids.** A word's id is `user~<uuid>`, its item id `{course}:user~<uuid>`, its facets `…#rec` (the word → its meaning) and `…#prod` (the meaning → the word). They can't clash with pack ids, and the review log, FSRS, the per-course filters (`allStates(courseId:)`), progression's XP and cloud sync of the log treat them like any facet. They are planned under the pseudo skill `kMyWordsSkillId` (`user~my-words`), which no pack has: the map, the skill stats, the tiers, mistake review and tough words iterate the course's own skills and never see them.
- **Loading.** `EngineSessionFactory(userWords:)` takes a loader of the course's words (the app reads the progress DB's `user_words` when a session starts, `providers.dart`). `SessionEnv.loadUserWords()` turns it into a `UserWordPool` once per session (deleted and empty words left out, oldest first); `EngineSession` hands a user-word slot to `UserWordPool.generate` instead of the selector. Grading goes through the ordinary templates (flashcard self-grade, `gradeChoice`, cloze `matchAnswer` with the accent setting), so results, events, retries, overrides and mistakes work unchanged.
- **Exercises** (`kUserWordTypes`; weights per stage like `kStageAffinity`: fresh → mostly flashcards, then choices, and writing once learning):
  - *flashcard*: recognise (the word; its meaning and the example on the back) or produce (the meaning → the word); the hint is the part of speech;
  - *multiple choice*: the word → its meaning, or the meaning → the word. The wrong options come from the learner's other words first, then from the course's lexicon of the same part of speech near the word's frequency (its lemma's when it was added from the reader, else a random middle rank; nouns, verbs and adjectives when the part of speech is unknown). An option sharing a meaning with the word is never offered (`OptionPicker` plus a meaning overlap check); with fewer than two wrong options the exercise isn't built;
  - *"Write the word"* (`cloze` with the whole word as the gap, `cloze.word`, the meaning as the hint; produce only): typed recall for keyboard and handwriting learners, a choice of four words for tap learners (typing is never required).
  `only`, the retry's missed type (`retryType`) and `avoid` are honoured as in the selector.
- **The "My words" session** (`factory.myWords(length: 12)`, mode `SessionMode.myWords`): due facets, most overdue first; then new words, at most six facets, oldest word first, recognise before produce; then the weakest of the rest by predicted recall. Each facet once, so a learner with two words gets four exercises (plus retries). Empty without words.
- **In lessons** (`LessonBuilder`): only **due** own words mix in, as reviews, and never a new one. A lesson takes `myWordsPerLesson(length)` of them (one in six: 1 for a quick lesson, 2 for a normal one, 3 for a long one, `LessonPlan.myWords`), spread evenly through the lesson (`LessonPlan.all`), in place of filler, so the length is unchanged. Gating and `currentSkillIds` use the skill's part only (`LessonPlan.skillPart`).

Tests: `test/engine/my_words_test.dart` (the pool and ids; a fresh word introduced with flashcards, later ones with choices and writing; wrong options from the other own words and the lexicon of the same part of speech, a lone word; writing typed or a choice and its grading; the session's order, recording and FSRS states, due first and retries, a deleted word; lessons: no new own word, due ones one in six and spread out, quick and long lessons; progression XP and summaries without tier changes; real packs it, nl and es).

## Reading (`reading.dart`, after v0.7.6)

The reader (docs/ui.md, "Reading") looks a pasted text up in the course. Pure Dart, synchronous, any script.

- **`ReadingLookup.of(course)`** (cached per course, about 60–150 ms once on the real packs) maps every written form, lower-cased, NFC and with straight apostrophes (`readingKey`), to **all** its readings (`WordAnalysis(itemId, form)`): lemmas and spelling variants, plurals, every accepted verb form (`'{tense}.{person}'`) and every inflection cell and its alternatives (`'infl:{table}.{cell}'`). Lemmas come first, then the more frequent item. Where the word is an item's own lemma only the lemma is kept (`mercato` is no "singular of mercato", `zijn` no "infinitive of zijn"); else the table cells, without the plain plural. Forms of several words (phrases of the lexicon such as `per favore`, compound forms `ho mangiato`, pronominal ones `mi alzo`) go to a phrase map.
- **Elision.** A word with an apostrophe is first looked up whole (Dutch `foto's`, Italian `po'`), else split after each apostrophe (`dell'` + `acqua`, French `l'` + `eau`) and at hyphens. An elided piece the course doesn't list is read as its full forms with a vowel (`l'` → la / lo / le, `dell'` → della / dello, `qu'` → que), but only for a short word ending in a consonant or `qu` / `gu`, so `po'` is never read as `poi`. A final apostrophe after a longer word is a closing quote.
- **`ReadingText.analyze(text, course)`** splits the text into lines (`ReadingParagraph`, long lines into pieces of about 1,200 characters at a sentence end, `continued`), tokens with their offsets (words, punctuation), sentences (ends `.!?…` with closing quotes) and phrases (the longest match from the lexicon's phrase map, at most six words, separated only by spacing, left to right). It marks numbers and names (capitalized, not in the course, not at a sentence start), and offers `tokenAt(offset)`, `sentenceAt(offset)`, `sentences` (the read-aloud order) and `coverage(known)`: running words counted (not numbers or names), known ones, distinct ones, and the percentage rounded down.
- Real packs: `andò` → `andare`, passato remoto, lui/lei; `gatti` → `gatto`, plural; `Sono andata` → `andare`, passato prossimo, io; Dutch `liep` → `lopen` (ik / jij / hij·zij); Spanish `hablaba` → `hablar`, imperfecto, `Hemos comido` → `comer`. Not found: words the pack doesn't have (Italian `una`, articulated prepositions such as `dell'`), which the reader marks as unknown.

Tests: `test/engine/reading_test.dart` (real it, nl and es packs: verb forms with person and tense, passato remoto, inflection cells, elisions, phrases and compound forms, names, numbers and unknown words, the share of known words, sentences and pieces of long lines, offsets, a 20,000-word text under 3 s; a French fixture for `l'eau` and `qu'il`; Cyrillic and Greek).

## Adding a template

1. Add the type id to `ExerciseType` and an `Exercise` subtype in `core/models/exercise.dart`. This is a contract change, so tell the UI side.
2. Implement `ExerciseTemplate` in `templates/your_template.dart`:
   - `kinds`: the facet kinds it serves.
   - `canGenerate`: deterministic and cheap.
   - `generate`: draw randomness only from `ctx.random` and ids only from `ctx.nextId()`, and filter every wrong option through `OptionPicker` with all valid answers as `forbidden`.
   - `grade`: pure.
3. Register it in `defaultTemplates()`, add its kinds to `ExerciseSelectorTypes.templateKinds`, and give it a row in `kStageAffinity`, the focus presets (JSON asset and `kDefaultFocusWeights`) and `RatingPolicy.defaultFastMs`.
4. Add a `case` to `validateExercise` in `test/engine/template_validity.dart` that checks validity against the course data independently of the generator, and list the skills where it must apply in `template_validity_test.dart`.
5. Run `dart run tool/sample_exercises.dart it` and `… nl` and read the output.

## Testing against real packs

`runTemplateValidity(CourseData course)` in `test/engine/template_validity.dart` is course-agnostic. `test/engine/real_pack_validity_test.dart` runs it on the bundled packs (`app/assets/courses/*.sqlite`), plus any packs named in `TOSK_EXTRA_PACKS` (directories or `.sqlite` files, separated by `;` or `,`, e.g. `TOSK_EXTRA_PACKS=../../tosk-data/dist` for a course that is not bundled; every `real_pack_*` test and the real-pack UI tests pick them up), for every source language: no failures, at least 20 exercises per applicable skill × template, every template used, at least 3 templates per skill (about 5 s for both packs).

`test/engine/real_pack_perf_test.dart` prints and loosely bounds the speed on the real packs (index warm-up, single exercises, 12-exercise lessons). On a desktop: warm-up about 20–130 ms once per course, a single exercise about 0.1 ms median and 2 ms p95, a lesson (generate, grade and record 12 exercises) about 6 ms median.

`tool/sample_exercises.dart` prints examples from a pack: `dart run tool/sample_exercises.dart nl --per 8` (a course id loads `assets/courses/{id}.sqlite`, a path loads that file). The committed samples are `docs/samples/{it,nl}_exercises.txt`; regenerate them after engine or pack changes and read the diff.

## Performance

Generation is synchronous, so everything a template needs repeatedly is cached per course in `CourseIndex` (an `Expando` on the `CourseData`):

- occurrences per verb and per sentence, auxiliary positions, finite forms per verb and tense, word splits and accepted-form keys;
- synonyms through inverted gloss and spelling indexes, meanings per item and language, sentences by normalized translation;
- `memo(key, …)`: templates cache their `canGenerate` answer (deterministic per facet, language and template parameters) and the conjugation grid its candidate groups per facet.

`normalizeAnswer` and `foldAnswer` are memoized (bounded caches), and `InMemoryCourseData.itemsNearFreq` sorts only a window of the frequency-sorted pool instead of the whole part of speech.

## Known limitations

- **Transform** relies on the course's `time_adverbs` list; an adverb missing from it, or a time implied by context, can still give an odd but grammatical sentence. Person changes are rare by design (pro-drop only). Italian imperatives are aligned to the `imperativo` cells (since pack 1.3; `Chiedi a un poliziotto!`, translations starting with *Ask …* / *Let's …*); one without `!` or such a translation can still be aligned as a present (the transform never crosses `tense_groups`, so it stays within the indicative).
- **Conjugation pick** needs stem/ending splits. Fully irregular tables (essere, avere, zijn, hebben) and compound tenses never get it; the grid and cloze cover them.
- **Spot the error and cloze** rely on the translation for pro-drop person swaps.
- **Person hints** come from the alignment. Where two persons share the form (Dutch `maakt` for jij and hij), a subject far from the verb can be missed; the pipeline then leaves the person open rather than guess, so such sentences are simply not used.
- **Sentence builder** accepts only orders attested in the course: the sentence itself, or another sentence with the same translation.
- **NFC** composition covers Latin letters (U+00C0–U+024F, U+1E00–U+1EFF). Other scripts pass through unnormalized.
- **Instruction strings** are in `engine/strings.dart` (English and Dutch); the UI may later move them to its localization.

# App screens (Phase 4) and integration

The UI lives in `app/lib/ui/`, plus `app/lib/main.dart`, `app/lib/app_bootstrap.dart`, `app/lib/app.dart` and `app/lib/providers.dart`.
Every dependency goes through a Riverpod provider. The app runs on the real data layer, exercise engine and progression; the demo courses in `app/lib/ui/demo/` are only a fallback when no course pack is installed.

## Start-up (`main.dart`, `app_bootstrap.dart`)

`main()` calls `bootApp()`, which calls the data layer's `openAppData()` and returns an `AppBoot` whose `overrides` go into the root `ProviderScope`:

| Override | Value |
| --- | --- |
| `appDataProvider` | the `AppData` |
| `progressStoreProvider` | `AppData.progress` (drift `ProgressRepo`, FSRS) |
| `courseCatalogProvider` | `PackCourseCatalog(app, fallback: DemoCourseCatalog())` (`ui/pack_course_catalog.dart`) |

- **Packs installed** (bundled `assets/courses/*.sqlite` count; they are installed on first use): the catalog lists them (summary metas from `PackInfo`, without loading the packs) and opens them with `AppData.openCourse`. Progress goes to `progress.sqlite`.
- **No packs**: the demo courses, labelled with a **Demo** chip next to the course title (and "Demo content" in settings). Their progress goes to a separate `progress-demo.sqlite`, seeded once with some history (`ui/demo/demo_seed.dart`), so demo practice never mixes with real progress. When packs appear (an app update with bundled packs), the next start uses them automatically.
- If the data layer can't be opened at all, `main()` logs the error and runs on the defaults (demo courses, in-memory progress).

Without overrides (most widget tests) the providers default to the demo courses and the data layer's in-memory FSRS `InMemoryProgressStore`.

The five top-level screens (**Map, Practice, Reference, Progress, Settings**; until v0.3 the second and third were Lab and Non-stop, now the two tabs of Practice) sit in a `StatefulShellRoute` (`ui/shell/app_shell.dart`). Below 600 px wide that shell uses a bottom `NavigationBar` (labels clamp their text scale on narrow phones, so "Reference" fits at 320 px). At 600 px and wider it uses a `NavigationRail`, extended with labels from 1100 px. The player, the sheets, the word page and the debug screen open on the root navigator, full screen. The tabs inside Practice and Reference switch an `IndexedStack` through a `TabController` (no swipeable page view: nothing slides on e-ink, no accidental swipes, both pages keep their state).

### Course picker (`ui/courses/course_picker.dart`)

`showCoursePicker(context, firstRun:)` opens a bottom sheet listing **every available course** (`availableCoursesProvider`: bundled and installed packs, a local Sarnami pack included, or the demo courses), each as a card with:

- the title, Demo / Unverified badges, source languages and version, "Added" in the subtitle and a 3 px border when added (never color alone);
- **+** (`IconButton.filled`, "Add to my courses") or **−** (`IconButton.outlined`, "Remove from my courses"; disabled for the last course: the app keeps at least one);
- **Preview** (expands in place, `coursePreviewProvider(id)` opens the course without making it active): the description (meta key `description`, now `CourseMeta.description`), "Learn Italian (it) · translations in English, Nederlands", counts (words, verbs, sentences, units, skills), the unit and skill outline, six sample words with glosses, and a sample sentence with its translation.

**Downloads (v0.4, `ui/courses/course_updates.dart`).** When the data layer has a `RemotePackSource` (`remotePacksProvider` = `AppData.remote`; null in widget tests by default, which hides everything below except as noted):

- **Check for updates** (a `TextButton` under the subtitle, or pull down on the list) fetches the index; the status line says "Checking…", "Last checked YYYY-MM-DD HH:MM", or a polite error ("Couldn't reach the course server…"). On app start `CourseUpdates.startup()` (from `AppShell`) loads the cached index (setting `packs.index_cache`) and checks silently when Settings → Course → **Check for course updates automatically** is on (default) and the last check (`packs.last_check`) is over 24 h old. Nothing is downloaded without a tap.
- **Installed courses** with a newer usable version get an **Update available** badge (outlined chip, icon plus text) and a tonal button "Update to v1.2.0 (17 MB)". Since v0.3.2 the map has no course switcher: Settings shows the update instead. A course row with an update gets a small dot (`UpdateDot`, filled black in black & white, tooltip and semantics "Course updates available") and "Update available" in its subtitle, and "Add or remove courses" reads "Courses (updates available)" with the dot.
- **Online-only courses** are listed after the installed ones (`course-online-{id}`): title, Unverified badge, source languages, version, "online", the description and **Download (12 MB)**. A course whose online version needs a newer app says so instead of offering a button. Demo courses count as not installed, so their card offers the real pack.
- **While downloading**: a determinate progress bar, "Downloading… 42% (5.1 MB of 12 MB)" and a cancel (✕) button. **Errors** are shown in the card (icon + text, never color alone) with Try again / Dismiss; the installed version keeps working. A newly downloaded course is added to my courses right away (with the usual "Where do you want to start?"); an update asks nothing and evicts the cached course, so it reopens on the new version. Progress is never touched.
- **Add course from file…** (an outlined button at the end of the list, with a one-line explanation; shown when `packInstallerProvider` is set, i.e. with a data layer) picks a `.sqlite` pack (`packFilePickerProvider`, the debug screen's file_picker flow) and installs it with `AppData.installPack`. A new course shows "Added Sarnami v0.1.0." and is added to my courses right away; a file for an installed course replaces it: "Updated Sarnami from v0.1.0 to v0.2.0. Your progress is kept." An invalid file: "This file couldn't be added as a course: …". The message is an outlined notice at the top of the list (a SnackBar would sit behind the sheet).

Done is pinned at the bottom. It opens from Settings ("Add or remove courses"); since v0.3.2 the map has no course switcher, only the course title. "My courses" is the setting `courses.added` (comma-separated, in the order added). **The rest of the app only shows those**: Settings and `activeCourseIdProvider` (the saved course among mine, else my first) go through `myCoursesProvider`. Removing a course only removes it from the list; its progress stays in the log, and adding it back finds it again. Installs from before the picker (no `courses.added`) count their active course as added (`AppSettings.myCourseIds`).

**First run:** with no course added (`needsCoursePickerProvider`), the shell opens the picker once ("Choose your course"). Closing it without adding anything adds the course shown underneath, so the app always has one. **Placement offer:** adding a course with no events in the log asks "Start from scratch" or "Find my level"; the latter makes it active, closes the picker and opens `/play/placement`.

### Stories (`ui/stories/`)

Graded mini-stories per unit (content and log convention: ARCHITECTURE.md, "Stories"). **Where they live:** reading is practice that earns (a little) XP, so the list is the third **Practice** tab; the map gets a small **book button** at the right end of each unit band header that has stories (`unit-stories-{unitId}`: the book and the count; a filled book once the unit's stories are unlocked, an outline before; 44 px tall, the band header plus the gap above the nodes, so it never covers a node; the unit title leaves room for it). It opens `UnitStoriesSheet`. Nothing new in the bottom navigation.

- **List** (`StoriesView`, `StoryTile`): per unit, cards with the target-language title, its translation and the state in words and icon (never color alone): "New" (book), "Read · best 3/4" (check), "Locked · preview" (lock, muted). Empty state for courses without stories. `storyRecordsProvider` (from the log) and `storyUnitsUnlockedProvider` (`storyUnitsUnlocked`: every facet-training skill of the unit started) drive it.
- **Reader** (`StoryReaderScreen`): app bar with close and the title, a progress bar over sentences + questions. Reading: a preview note when locked, the translated title, a "New word: … = …" note for the story's new word, then the sentences revealed one at a time by **Continue** (the newest slightly bolder, the list scrolls to it; jumps instead of animating with reduced motion). Every aligned word is a `TappableSentence` word (popover with the gloss and "Open in reference"); each sentence has a translate toggle (`story-translate-{i}`, tooltip "Show/Hide translation") that shows its translation in italics below. After the last sentence the button becomes **Questions**. Questions: "Question n of N", the target-language prompt (when there is one) above the source-language one, the options as `OptionButton`s at the bottom (thumb zone; the shared right/wrong looks, ✓/✗ and strikethrough in black & white), in a stable story-specific shuffled order; one tap answers, with correct/wrong sound and haptic, a "Right!"/"Not quite" verdict (icon and words) and the explanation if any; **Next question** / **Finish** stays disabled until answered. Result: "Story complete!", "n of N questions right", "+X XP" (the progression rule applied to the story facet's state before the read) and "All stories"; **Done** closes. The pinned bottom button sits in a `SafeArea`, so it clears the system navigation bar (edge-to-edge).
- Finishing records the story read event (`kStoryReadType`) and bumps `progressRevisionProvider`, so the header, the daily goal and the list update.

### Word popovers: tap a word for its translation (`ui/common/word_popover.dart`)

Target-language sentences show their aligned words (the engine's `TokenRef`s, see `docs/engine.md`) with a dotted underline; tapping one opens a small popover anchored under (or above) the word, kept on screen: the headline from `glossForToken` (`mangiamo → mangiare · noi · present`, nouns with their article: `il pane`), the pronounce button (with a voice) and a ☆ to star the word (v0.4), the glosses in the source language, and "Open in reference" (`/word/:itemId`). It is a `PopupRoute` on the root navigator: no barrier color, no transition, dismissed by a tap outside or Back; in black & white a white card with a 3 px black border and no shadow. Unaligned words and punctuation stay plain text.

| Exercise | Where |
| --- | --- |
| cloze | the words before and after the gap (`tokenSpans` around the gap widget); after checking, the filled gap too |
| spot the error | **after checking only** (before, a tap is the answer): the word tiles; the wrong word shows the correct word's gloss |
| multiple choice, sentence → meaning | the prompt sentence |
| multiple choice, meaning → sentence | after checking, the correct option's sentence |
| transform | the source sentence |
| sentence builder | after checking, the answer sentence ("answer-sentence" row under the prompt) |
| reference | example sentences on the word page |

**Never the answer:** before checking, no word aligned to the exercise's own item is tappable (`hideItemUntilAnswered`): not the gapped verb's other words (`heb … gegeten`), not the noun of an article question, not the asked word in a sentence. Options and tiles are never tappable. The feedback panel itself is unchanged (it belongs to the AI-explanation work); the correct sentence is tappable in the exercise area instead (cloze gap, MC option, sentence builder row).

### Test out, placement and tough words (UI)

- The skill sheet's **Test out** runs `/play/testout/:skillId` (about 10 exercises, no re-asks). The summary's `AssessmentResultCard` (`ui/lesson/assessment_result.dart`, shown through `SessionSummaryView(header:)` for any `AssessmentSession` with an `outcome`) shows the verdict with an icon and words (✓ "Tested out!" / ↻ "Not yet"), the score and the pass mark. Passing credits the skill (see `docs/engine.md`), so the map shows it learned and the next skills unlocked after the session's progress bump.
- **Placement** comes from the course picker's "Find my level" (see above).
- **Tough words** (`toughWordsProvider`, progression's `toughWords` over the facet states with the Settings threshold): "Tough words (N)" on the Progress page (with the first three words) and in the mistakes screen's bottom bar, both starting `/play/tough`.

### Lesson player (`ui/lesson/`)

- `PlayerScreen` drives a `PracticeSession` through these phases: loading → exercise → Check → feedback banner → Continue → … → summary. There are also empty and error states.
  - The progress bar is `answered / plannedLength`. Endless sessions show "N answered · M correct" instead.
  - Exit asks for confirmation (the close button, Esc, or system back). In non-stop, exiting stops the run and shows the summary.
  - Desktop shortcuts: 1–9 pick options or tiles. Enter checks, continues, or reveals a flashcard. Esc leaves. Shortcuts are ignored while a text field has focus.
  - After a session (finished, quit or a non-stop run stopped mid-way) the player bumps `progressRevisionProvider`, which refreshes the map stats, the header and the progress pages. A player whose route is removed some other way with answers recorded stops its session and bumps it from `dispose`.
  - **First-time intros** (`ui/lesson/intro/`): the first time a learner meets an exercise type, the player shows one screen before it (`ExerciseIntroView`: icon, title, what to do, a small static example from the course's own data via `introExample`, e.g. `pens___ → pensiamo`, `present: penso → present perfect: ho pensato`, never the current exercise's words; "Got it" pinned at the bottom, Enter on desktop). The response time starts after Got it. Seen types are the account-wide setting `intro.seen` (`introSeenProvider`). The app bar's (?) (`exercise-help`) reopens the explanation as a sheet. Texts are in `exercise_intros.dart` (English, one file). Intros are off under `flutter test` (`exerciseIntrosEnabledProvider`) unless a test enables them.
  - **Non-stop scoring.** The player keeps a progression `NonStopRun` and feeds it one graded exercise at a time from the engine's `EngineSession.results` stream: `run = run.applyResult(event.exercise, event.result, at: toStoredTime(event.events.first.at))`. When a run starts a bonus round (`NonStopSignal.bonusRoundStarted`) it calls `NonStopSession.enqueueBonus(types: run.preferredTypes, count: round.targetAnswers)`; `_advance` waits for the result event of the last submit before drawing the next exercise, so the bonus applies to the very next one. The HUD (`NonStopHudSlot`) shows the run.
  - **Contract (engine ↔ progression ↔ UI).** The engine records every facet outcome of one exercise with the same `at` (`env.now()`), the session id and mode `nonstop`; the UI feeds `NonStopRun` with that recorded `at` (UTC, whole milliseconds, as stored). The best run replayed from the log (`bestNonStopRunProvider`) then equals the live score. One known gap: a wrong *re-ask* after a mistake records no event, so the live run breaks the combo while the replay doesn't see that answer.
  - **"Explain answer with AI"** (right and wrong answers) uses the core `Explainer` (`explainerProvider`).
    - It is the cached AI explainer when a provider and key are configured. Otherwise it is `NullExplainer` and the button doesn't exist.
    - The context is `buildExplainContext(...)`, with the engine's `mistakeContext(exercise.id)` when there is one.
    - The reply streams into `AiExplanationSheet` (`ui/ai/`).
  - **"Report"** (always shown) opens `FlagSheet` (`ui/feedback/`). After Submit it reads "Reported" and is disabled. Details are in `docs/feedback.md`.
  - **Sounds:**
    - `soundServiceProvider` warms up at session start.
    - The select tick (plus a selection haptic) plays through `ExerciseView.onSelect` on every tap that changes the draft (not typing) and on match-pairs cards.
    - Correct or wrong plays on Check.
    - At the end, complete plays, or level up when the session gained a level.
    - Bonus plays when a non-stop bonus round starts.
- **Thumb zone.** Every exercise widget returns an `ExerciseLayout(prompt:, controls:)` (`exercises/exercise_layout.dart`, a small render object). The player gives the exercise at least the visible height of its scroll view, so the prompt sits at the top and the interactive part (options, endings, tiles and answer line, the grid and its tile bank, the match columns, the flashcard buttons, the spot-the-error sentence) at the bottom, just above Check / the feedback panel. Taller content stacks and scrolls. The column is centered and at most 640 px wide. Options, tiles and grid cells are at least 48 px tall (tiles also 48 px wide). `test/ui/thumb_zone_test.dart` checks every type at 400×800 and 1280×800.
- `exercises/`: one widget per type, all subclasses of `ExerciseWidget<E>`.
  - Each widget reports a draft `Answer?` through `onChanged`.
  - Flashcard (self-grade) and match pairs (once everything is matched) submit themselves through `onSubmit`.
  - With `result` set, a widget shows its marks: right and wrong options, per-cell ✓/✗ with the expected form for grids, and the correction for spot-the-error.

  | Type | Widget | Answer |
  | --- | --- | --- |
  | flashcard | `FlashcardView` (Show answer, then Again/Hard/Good/Easy) | `SelfGradeAnswer` |
  | multiple_choice | `MultipleChoiceView` (the optional `hint` under the prompt, e.g. the meaning in `___ ragazzo`) | `ChoiceAnswer` |
  | match_pairs | `MatchPairsView` over a pure `MatchBoard` state machine (`match_board.dart`): either order; taps resolve synchronously; matched cards ignore taps; a wrong pair marks **both** cards wrong (a 600 ms flash that clears only that pair; with reduced motion until the next tap); a tapped card stops flashing and shows as selected. After checking, both cards of every wrong pair stay marked and a "Mixed up" list names the pairs | `MatchAnswer(matches, missed, wrongPairs)` |
  | conj_pick | `ConjPickView` (`mang___`, person and tense chips, ending options; the empty ending is the engine's `kNoEnding` `–` and fills nothing) | `ChoiceAnswer` |
  | conj_grid | `ConjGridView` (tap a cell, then a tile; prefilled cells greyed; tap a filled cell to return its tile; tiles may repeat, one per asked cell) | `GridAnswer` (`''` for prefilled cells) |

  | listen_pick | `ListenPickView` (v0.5: a 112 px play button and "Slower", options at the bottom; plays once by itself; the translation and the tappable right sentence only after checking) | `ChoiceAnswer` |

    - The player passes "Explain answer with AI" (`ai-explain-button`, only when AI is configured), "Star" (`star-button`, v0.4: opens the Star sheet; reads "Starred" with a filled star once the exercise, its word or its sentence is starred) and "Report" (`flag-button`).

### Skill map (`ui/map/`)

- `map_layout.dart` is pure and unit-tested:
  - **layer** is the longest prerequisite path. Unknown prerequisites are ignored, and back edges are skipped, so a cycle can't hang the layout.
  - Each **unit is a horizontal band**, stacked in unit order. Within a band, the distinct layers of its skills become rows.
  - Rows are centered on the widest row.
  - Crossings are reduced with the **barycenter heuristic**: alternating down and up sweeps, keeping the ordering with the fewest crossings.
  - **`pos` override**: `posY` sets the row inside the unit band and `posX` the column. A pinned node is fixed, and free nodes in the same row take the remaining columns.
- `skill_map_view.dart` (v0.6: the map is a tree of **storybook branches**, see `docs/brand-overhaul.md`):
  - `MapGeometry` turns the layout into pixels. Cells are 64–144 px wide (long skill titles fit on two lines), fitted to the width, and multiplied by the zoom. Each node gets a square box of at least 48 px (the stone, its ring and the sparkles).
  - **Direction.** `MapDirection` / `kMapDirection` (top of `skill_map_view.dart`) is the one setting for the growth direction. `topDown` (today): the first unit at the top, scroll down. `bottomUp`: the roots at the bottom, the first unit lowest, later units above, scroll up; `MapGeometry` reverses the band order and the rows inside each band (`visualRow`), the branch painter draws every bough from its parent to its child whichever is higher (`edgePath`), and the marker, bands and titles follow the geometry. To try it: change the constant and have `MapScreen` start scrolled to the bottom. `test/ui/map_painters_test.dart` checks both directions.
  - `MapEdgesPainter` paints the prerequisite edges as **boughs** (`bough.dart`: `BoughShape.build` computes a bough's geometry once, seeded, and `BoughShape.paint` draws it; `paintBough` does both; the map keeps the shapes between frames, `MapEdgesPainter.boughShapes()`): a tapered bark silhouette (width from `branch-style.json`'s `width_main` as a fraction of the node diameter) with 1–2 Gaussian knuckles and a crease across each, bark grain dashes and hatching on the shadow side, an ink outline whose weight follows the light (top right), and a twig with a pinnate **ash leaf** on the longer boughs. Forks and joins come from the layout's edges. Boughs to locked skills are thinner and paler (gray in black & white). An edge whose straight path would pass behind another node (typically one skipping a unit) detours through the nearest free lane between columns (`detourLane`). Unit titles (a serif, wordmark-style title per bough) and node titles sit on the band color above the branches, so no bough runs through text.
  - `ink_art.dart` holds the drawing primitives (the Dart port of the art kit's generator): `Polyline.sample`, `inkStroke` (a filled band, thin on the lit side, heavy in the shadow, with a slow hand wobble), `hatchRegion`, `inkRing`, `twinklePath` / `paintTwinkle`, `paintAshLeaf`, `paintSprout`. `medal_art.dart` (v0.7.1) adds the medal pieces: `CrackPattern` (the cracks of decay), `paintLaurel`, `paintShine`, `paintShineSweep`, `paintStipple` and `twinkleMotion`. Everything is seeded (`inkSeed(id)`), so a node or bough looks the same on every frame.
  - `branch_style.dart`: `BranchStyle` is the painter spec. Its defaults equal `assets/brand/branch-style.json` (generated by `app/tool/brand/make_tosk.py`); `branchStyleProvider` loads the asset and `BranchStyle.fromJson` reads bough widths, knuckles, grain, hatch, outline, leaf scale, twig sizes, and the nodes' gleam (and which tiers get it: gold), `extent` (1.75 r), per-tier sparkle (twinkles / dots / rays in units of r; gold's rays spread over an arc with short rays between, `Rays.arc_deg` / `short_r1`, and its `Laurel`) and the `Cracks` (start, max, chip thresholds), so a regenerated spec is followed without a code change. A unit test checks the bundled spec parses to the defaults.
  - **Motion (v0.7.1, `map_motion.dart`).** With motion on (`twinkle`, from `twinkleProvider`: motion on and not under `flutter test`; `swayLeaves` defaults to the same; never with reduce motion or in black & white) the medals twinkle and the ash leaves sway when the map scrolls. It is kept cheap:
    - **One ticker** in `SkillMapView`'s state for the whole map, no controller per node. It runs only while something moves: metal nodes in view (`MapMotion.visible`, the viewport in map coordinates, from the nearest `Scrollable`), or leaves still settling after a scroll (the scroll position's listener starts it). It stops by itself when the leaves are still and no metal node is in view, is muted by `TickerMode` when the map is off screen (another route or tab: go_router's indexed stack disables inactive branches) and stops while the app is not resumed (`WidgetsBindingObserver`).
    - **Layers.** The stones (each in its own `RepaintBoundary`), the boughs (`MapEdgesPainter` on a `RepaintBoundary`, painted once per layout) and the whole map content are static layers, so scrolling only moves them. `MapSparklePainter` paints every moving twinkle of the visible metal nodes on one layer above the stones (the stones then leave their twinkles out, `NodePainter.paintTwinkles`), repainting through a `Listenable` at about 30 fps; `MapLeavesPainter` paints the leaves on a layer above the boughs (the boughs then leave them out, `paintLeaves: false`). Neither rebuilds a widget.
    - **Twinkles** (`twinkleMotion`): silver breathes (scale 1 ± 0.14, opacity 0.82–1, 2.4 s, phases offset per twinkle and node) with a flare every 6.5 s; gold breathes faster and deeper with a flare every 4.5 s; bronze's single glint rests and flares (to 1.45×, a slight turn) for 0.7 s every 5.2 s.
    - **Leaves** (`LeafSway`): a damped spring per leaf (about 1.5 Hz, damping ratio about 0.2, both varied per leaf) that leans with the smoothed scroll velocity (more for leaves pointing sideways, at most 0.5 rad) and swings back when the scrolling stops. Only leaves near the viewport are simulated, at most `kMaxSwayLeaves` (24); each leaf is drawn once into a cached `Picture` and replayed at its angle.
    - Tests count paints (`NodePainter.debugPaintCount`, `MapEdgesPainter.debugPaintCount`, `MapSparklePainter.debugPaintCount`, `MapLeavesPainter.debugPaintCount`): see `test/ui/map_motion_test.dart`.
  - **Tosk marker.** `currentSkillId` (the first available or started skill in course order) gets Tosk's head badge (`ToskPose.marker`, 40–56 px) at the top left of its stone, `IgnorePointer` with the semantics label "Tosk: continue here"; the node underneath stays the tap target.
  - `test/ui/map_big_course_test.dart` runs a 10-unit, 30-skill course (`test/fixtures/big_map_course.dart`) at 320 px to desktop and text 1.3: every node reachable with a 48 px target and a semantics label, every band title present, no horizontal scroll, and no edge behind a node.
  - The map scrolls vertically, and horizontally only when it is wider than the screen (zoomed in). There's no horizontal overflow at 320 px.
- Tapping a skill opens its sheet first (what it is, tier and next tier, then Start lesson); a **locked** skill's sheet says "Recommended first: …. You can start this one anyway." "What's fading" is hidden until something was practiced.
- `skill_node.dart` and `node_painter.dart`:
  - `NodePainter` paints the **stone medallion** with the six states: locked (paper, hatched, one faint ring), available (cream, two rings, a sprouting leaflet), started (cream plus the strength ring: a dotted track at 1.24 r, the filled part a heavy leaf-green arc with an ink cap dot), and the three medals, which differ in colour **and** shape (v0.7.1) so they read at a glance, in black & white and for colour-blind learners:

    The shadow crescent (lower left) is hatched on every unlocked state. Sparkle positions come from the spec. `sweep` (0..1) draws a shine passing across the stone (the promotion moment); `paintTwinkles: false` leaves the twinkles to the map's sparkle layer.

### v0.5: handwriting, listening, e-ink extras

**Answer input: Tap / Type / Write** (Settings → Challenge; `lesson.answer_input` = `tap` | `type` | `handwrite`). Write is only offered where the recognizer runs (`inkSupportedProvider`: ML Kit on Android and iOS; not on the web, Windows or under `flutter test`); a `handwrite` restored from a backup elsewhere acts as Tap. With Write, `SessionOptions.preferredInput = ink` (cloze is free text, as for typing) and the production exercises put a writing pad (`InkPad`, `ui/ink/ink_pad.dart`) at the bottom instead of the text fields:

| Exercise | Pad | Answer |
| --- | --- | --- |
| cloze | the free-text input (`InkAnswerInput`); context: the words before the gap | `TextAnswer(ink, candidates)` |
| conjugation pick | "Write the ending"; context: the stem; the ending or the whole form | `TextAnswer(ink, candidates)` |
| conjugation grid | one pad under the table for the selected cell (150 px); "Next cell" (the last says "Done" and checks); tapping a cell rewrites it; no tile bank | `GridAnswer(ink, candidates: per cell)` |
| sentence builder, transform | segmented: "Next word" commits a part and clears the pad; the parts' readings are combined (lowest rank sum first, up to 9; the top five count) | `TextAnswer(ink, candidates)` |

- **The pad.** About a quarter of the screen (150–240 px), a dashed writing line, "Read as: …" above it (a live region) and 48 px buttons: Undo stroke, Clear, Type instead (a `TypedAnswerField` with the accent bar for this exercise; "Write instead" goes back), plus the exercise's action. Raw pointer events through a `Listener`; an `EagerGestureRecognizer` claims every pointer on the pad, so writing never scrolls the exercise. Palm rejection: once a stylus wrote on the pad, finger touches are ignored. Recognition runs 450 ms after the last stroke (`InkRecognizer.recognize` with the course model, the pre-context and the pad size); a newer request supersedes an older one. After checking the pad collapses to its reading.
- **Model.** `inkModelProvider` (`ui/ink/ink_providers.dart`) resolves the course's model (`inkLanguageTags(target)`: the target itself; Sarnami `hns` → `nl`, below) and its status. Until it is on the device the pad shows the one-time download ("about 20 MB, Wi-Fi recommended; after that it works offline"; ML Kit reports no byte progress, so an indeterminate bar, or an hourglass with reduced motion), errors with "Try again", or "Handwriting isn't available for this language". Settings shows the same model with Download / Delete. Downloads don't require Wi-Fi (`isWifiRequired: false`); ML Kit keeps the model for offline use.
- **Sarnami.** ML Kit has no Sarnami model. The course uses Dutch spelling conventions (`toe`, `oe`, `hamlog`), so the Dutch model (`nl`) is used: it reads the plain letters well but never produces `ṯ ḏ ṟ ã õ`. With lenient accents (the default) such answers count with "Watch the accent"; with strict accents they are wrong (type instead). Settings says so under the model.
- **ONYX pen.** On Boox devices (`penSurfaceProvider`; Settings → E-reader → "Fast pen drawing", `eink.onyx_pen`, default on) the pad opens the Onyx pen SDK's raw drawing on its rectangle (physical pixels, tracked after every frame), so the stylus draws with e-ink latency; the strokes come back over `tosk/onyx_pen` and are painted and recognized like Flutter strokes (Flutter ignores stylus events while the SDK draws; fingers still draw through Flutter). Undo and Clear drop the SDK's overlay, the pen's eraser removes the strokes it touches, and raw drawing pauses while the pad is disabled, another route (a dialog, a popover) is on top, or the app is paused. If the SDK fails to open, the pad draws with Flutter.

**Listening.** `speakerProvider` (`speech/`) is `flutter_tts` (`TtsSpeaker`) or `NullSpeaker` under `flutter test`. `TtsSpeaker` first sets the engine up, once, before any other call: `awaitSpeakCompletion(true)`, then the audio output (Android: `setAudioAttributes(USAGE_MEDIA, CONTENT_TYPE_SPEECH)`, a call added to the vendored plugin; iOS: the shared session, `playback` with `mixWithOthers`; web and macOS: nothing). Voices: on Android from `getVoices`, installed ones only (`pickVoice`: a voice with the engine's `notInstalled` feature doesn't count; the locale `pickVoiceLocale` prefers; on-device before network), set with `setVoice`; when the engine lists no voices, and on other platforms, the best locale among `getLanguages` (on Android also `isLanguageAvailable`) with `setLanguage`. Normal and ~60 % rates come from the engine's range. A lookup that failed or timed out (an engine still starting) isn't cached. The result is a `VoiceStatus`: `ready`, `notInstalled` (listed without its data), `missing` (no voice for the language) or `unavailable` (no engine, no speech on this platform). The patched Android plugin returns the engine's error code from an awaited `speak` that failed; `ERROR_NOT_INSTALLED_YET` (-9) marks the language `notInstalled` and invalidates `courseVoiceStatusProvider`, so the 🔊 buttons go and the running session skips its remaining listening exercises (`voiceNotInstalledProvider`). Every lookup logs one `[tts]` line (the status, the chosen voice and the engine's voices for the language) for device debugging. `courseVoiceStatusProvider` holds the status for the active course's language, `courseVoiceProvider` whether it is `ready` (Sarnami never); `listeningProvider` = a voice and Settings → "Listening exercises" (`lesson.listening`, default on, shown only with a voice) → `SessionOptions.listening`, so the engine generates `listen_pick` only then, and the lab lists "Listen and pick" only then. Windows has no voice (docs/release.md).

**Pronounce buttons** (`ui/common/pronounce_button.dart`, `canPronounceProvider`): a 48 px 🔊 on word popovers (the tapped word), flashcards (the target side: the front when recognizing, the back once revealed when producing) and the word page's app bar (the word with its article). Absent without a voice.

**"Install a voice" notice** (Android only, `voiceNoticeProvider`, `voiceNoticeFor`): when the course language is `notInstalled`, or `missing` for a two-letter language (Sarnami `hns` has no voice anywhere, so it never nags), the app shell shows a snack bar once per language and device ("No sound? Install an Italian voice in Android text-to-speech settings.", action **Settings**, which opens Android's text-to-speech settings through `tosk/device` `openTtsSettings`; remembered in the device-only `speech.voice_notice`), and Settings → Challenge shows a "No Italian voice" row with **Open** in place of the Listening exercises switch. Tests: `test/speech/tts_speaker_test.dart` (set-up order on Android, iOS and elsewhere, the voice choice, not installed when listed or while speaking, the fallback to languages, failures not cached, the notice rules and the once-per-language claim, the sound effects' audio context), `test/ui/voice_notice_test.dart` (the snack bar once, none with a voice, off Android or without an engine; the Settings row; color and black & white at 320×568, 360×640 and 1280×800 with text 1.3; listening exercises skipped once the voice is not installed).

**Audio stream.** All app audio plays on the **media** stream (controlled by the media volume, like YouTube or a music app): speech with `USAGE_MEDIA` / `CONTENT_TYPE_SPEECH`, sound effects with `USAGE_MEDIA` / `CONTENT_TYPE_SONIFICATION` and no audio focus (`kSfxAudioContext`, `audio/sound_service.dart`; they used to be `USAGE_ASSISTANCE_SONIFICATION`, the system stream, which follows the ring volume and is muted on silent). `MainActivity` sets `volumeControlStream = STREAM_MUSIC`, so the volume keys change the media volume in the app even when nothing plays. iOS: both use the `playback` category with `mixWithOthers` (the learner's music keeps playing; the silent switch doesn't mute the app, as in other media apps). Tests: `test/ui/v05_features_test.dart` (the Write setting and model tile; writing in cloze, conjugation pick, grid with "Next cell", sentence builder in parts; candidates accepted; undo and clear; the model download in the pad; a language without a model; the keyboard fallback; palm rejection; writing doesn't scroll; the Onyx pen surface opening on the pad's rect, its strokes recognized in pad coordinates, the overlay cleared on undo, paused under a dialog, closed on leaving, the fallback when it fails; the full refresh after the summary and on leaving in black & white, off in color unless set, never off ONYX; the E-reader section; listening off without a voice, the lab chip, autoplay, slow replay, the translation after checking, the setting; pronounce buttons), `test/ui/v05_bw_test.dart` (every new state pixel-scanned in black & white at every e-ink harness size; color, dark and text 1.3 at 320×568, 360×640 and 1280×800), `test/ui/v05_units_test.dart`. ## Tests

`test/qa/qa_walkthrough.dart` (no `_test` suffix, so not in the default run) walks the app on the **real packs with real fonts** and saves a PNG of every step: `QA_OUT=<dir> flutter test test/qa/qa_walkthrough.dart`. It covers both courses, every exercise type through the lab, a lesson with feedback states, the progress pages, mistakes, settings, dark mode at 320 px and text 1.3, desktop, a 30-skill map, and black & white at phone, 6" e-reader and Boox sizes. The desktop app can run on a separate profile with `flutter run -d windows --dart-define=TOSK_DATA_DIR=<dir>`.

`app/test/ui/` runs the app on the defaults (demo courses, in-memory FSRS store, fixed clock, UTC calendar). `pumpApp` overrides `sessionFactoryProvider` with the test fake `fakes/demo_session.dart` (hand-made exercises, a fixed one per type) so layout and flow tests are deterministic; `pumpApp(engine: true)` uses the real engine. `app/test/app/` runs the real wiring over the data layer's fixture course.

# tosk visual overhaul and branding

*Plan agreed 14 October 2026. Implement exactly this; ask nothing, decide and document.*

## Decisions (from the owner)

- **Names:** the app is **tosk** (after Ratatosk). The GitHub org is **linguaperta**, and the repos get renamed later.
  - The display name becomes "tosk" now.
  - *(Superseded 20 Oct 2026: renamed to `org.linguaperta.tosk` / `tosk.exe`, see docs/hosting.md.)* **Do not** change the Android/iOS package id (`io.github.timoverlaan.tosk`) or the Windows exe name `tosk.exe`. Changing them would orphan user data, and the Windows secure-storage key name is derived from the exe name.
- **Mascot:** Tosk, the red squirrel. The chosen art is the **storybook style, variant c** (upright, confident pose): `app/assets/brand/explore/storybook/tosk-c.svg` (+ `-mono`), with its generator `explore/storybook/make_storybook.py` and its palette.
- **Wordmark:** "tosk" in **Gelasio Bold** as paths (OFL; font in `explore/storybook/fonts/`). Use the plain version; the leaf version is optional.
- **Course paths are branches** of a tree (an ash; Yggdrasil in spirit). Keep it **light on Norse mythology**: no runes, dragon, eagle or well, because it clashes with learning other languages.
- **Skill states:** locked, available, in progress (strength ring), bronze, silver, gold, following the storybook `node-states.svg`. **Gold, silver and bronze must look more sparkly**:
  - **Gold:** several 4-point twinkle stars plus rays.
  - **Silver:** fewer twinkles.
  - **Bronze:** a single glint.

  In motion mode they can twinkle subtly; with `reduceMotion` or B/W they are static. B/W keeps the hierarchy through ring count, rays and twinkle shapes.
- **The app needs branches, not the whole tree.** The full tree is optional decoration (splash, course picker, progress overview).
- **E-ink:** every asset needs a colour and a pure black/white version, and the existing B/W mode must keep passing its pixel-scan tests.

## Work split

### A. Art kit (`app/assets/brand/`, generated by `app/tool/brand/`)

Promote the storybook generator to `app/tool/brand/make_tosk.py`. Keep it dependency-free, except fontTools for the wordmark. It produces final assets into `app/assets/brand/`; `explore/` stays as the archive.

1. **Tosk variant c:** full body, head crop, and a small **map marker** (head/bust that reads at 40–56 px). Colour and mono.
2. **A few extra poses** in the same style for UI moments, reusing the variant c face and proportions:
   - celebrating (lesson complete)
   - thinking/reading (empty states, stories)
   - sleeping/curled (nothing due today)
   - pointing/explaining (intros)
3. **Node states** with the sparkly tiers, as SVG references (the app paints them; see B).
4. **Ash leaf sprites:** 2–3 variants.
5. A **branch style spec** (`app/assets/brand/branch-style.json`): colours, width taper, bark grain parameters, leaf placement rules, so the Dart painter matches the art.
6. **Launcher icon sources:**
   - a 1024×1024 icon (Tosk variant c head in the bookplate frame)
   - an Android adaptive foreground (safe zone) and background (paper colour), plus a monochrome themed-icon layer
   - a splash image (Tosk + wordmark, centred) and a splash background colour
7. **PNG exports** of everything the app shows as raster, at 1x/2x/3x where used, colour + mono. Render them with headless Edge (the explore agents already used this pattern). Keep assets small and the total added app size modest (< ~1.5 MB).
8. Update `docs/brand-sheet.png` to the final kit.

### B. App integration (`app/`)

1. **Theme:** the storybook palette as the default skin (light + dark), Gelasio for titles/headings and the wordmark (bundle the OFL font as an app font asset with its licence), the existing UI font for body text. Paper-textured feel through colour only (no heavy images).
2. **Display name** "tosk":
   - **Android:** label.
   - **iOS:** CFBundleDisplayName.
   - **Web:** title and manifest name, short_name, theme colours.
   - **Windows:** window title (exe name unchanged).
   - **macOS and Linux:** titles.
   - **In-app:** strings.
3. **Launcher icons and splash** from A's sources, with `flutter_launcher_icons` and `flutter_native_splash` as dev dependencies (approved). Android adaptive + themed icon; the iOS AppIcon set; web icons; the Windows .ico.
4. **The map, redesigned as branches:**
   - A `CustomPainter` that draws storybook branches between the layout's skill nodes: tapered bark, grain dashes and ash leaves along the way, following `branch-style.json`.
   - Forks and joins come naturally from the layout's edges.
   - Unit bands become boughs or sections with a subtle header (a wordmark-style serif title).
   - Nodes are painted with the six states and the **sparkly tiers** (twinkle animation only when motion is on).
   - **Tosk marker** at the current/next skill.
   - Keep the current top-down scroll, but make the direction a single, well-isolated setting in the layout code, so roots-at-bottom (scroll up) could be tried later. Document how.
   - Everything stays tappable (48 px targets), with semantics labels, phone-width safe, and B/W-correct.
5. **Mascot in the UI:**
   - the lesson summary (celebrating)
   - empty states: no mistakes, no stories, nothing due (thinking/sleeping)
   - first-time exercise intros (pointing)
   - the course picker header
   - the about/settings header with the wordmark
6. **Tests:**
   - update the goldens and the B/W pixel-scan and overflow harnesses for every changed screen;
   - painter unit tests (no exceptions on degenerate layouts, B/W paints only black/white);
   - full `flutter test -j 2` green, `flutter analyze` clean.
7. **Docs:** `docs/ui.md` (skin, map painter, assets, how to regenerate icons and splash), README title and screenshots.
